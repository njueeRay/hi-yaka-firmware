# 50 文档与飞书同步

## 双端原则

Markdown 是可审计本地工作真值；飞书是团队阅读、协作和附件入口。每一对文档在 `docs/governance/FEISHU_SYNC_REGISTRY.md` 登记本地路径、飞书 URL/token、revision、最后同步时间和差异状态。

## 更新规则

1. 修改前读取本地和飞书现状；
2. 区分事实、需求、假设、建议和未知；
3. 局部修改，不覆盖飞书中仍有价值的历史、图片或评论；
4. 上传的审计附件保留日期/版本，并记录 SHA-256；
5. 回读飞书 revision 和关键章节，确认更新成功；
6. 同步登记写回 Git，并在变更日志中记录影响范围。

硬件主文档只摘要当前有效结论，原理图/PCB/SMT 报告作为版本化附件。若附件与活体 EDA 冲突，标注失效并重新生成审计，禁止静默改写旧附件。
