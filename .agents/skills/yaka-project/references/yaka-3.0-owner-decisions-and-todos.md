# HiYaKa 当前角色、Owner 决策与待办

> 更新时间：2026-11-02（Asia/Shanghai）
> 文档状态：当前决策台账  
> 适用范围：HiYaKa 产品、硬件、固件、制造、验证与文档治理
> 目的：只保留仍生效的决定、真正需要 Owner 裁决的事项和各角色当前责任；历史推演、已经关闭的 ECO 和普通工程任务不继续伪装成 Owner 待办。

## 1. 使用规则

1. 产品行为、范围、成本、不可逆数据策略和量产放行由 Owner 决定。
2. 原理图、驱动、构建、测试和文档同步等可逆工程工作由对应角色按批准方向执行，不要求 Owner 逐项代替工程判断。
3. `已冻结` 表示已经形成当前合同；`暂行基线` 表示可进入实现和验证但仍可被实测修订；`待 Owner 决策` 表示不能由工程擅自冻结；`待团队输入` 表示需要资料或证据，不是产品决策。
4. 完成的事项进入“已关闭/被取代”，不在当前待办区重复出现。
5. 本文不是 PRD、缺陷库或发布报告。产品要求见 `yaka-3.0-prd.md`；工程进度见固件 PRD；正式 ADR 见飞书“决策与版本记录”。

## 2. 当前角色与职责

| 角色 | 决策/交付责任 | 当前重点 |
|---|---|---|
| 项目 Owner | 产品目标、范围、交互、成本、不可逆数据策略、量产放行 | 关闭仍影响产品行为的 P1 决策 |
| 产品与交互 | 把 Owner 决定转为页面、按键、状态、文案和验收用例 | 首页、按键、录音、NFC、异常反馈 |
| 硬件研发 | 活体 EDA、器件/网络/PCB、制造资料和硬件变更证据 | 首板 Bring-up 支持与实装差异追溯 |
| 固件研发 | 板级配置、驱动、状态机、数据可靠性、上游同步和构建 | 先完成 M1 首板安全验证，再逐项验证已就绪的 M2–M5 L0 适配 |
| 制造/供应链 | BOM/CPL/Gerber/DFM、替代料、装配预览和下单签核 | 保存最终 DFM、器件方向和订单证据 |
| 验证 | L0–L3 测试、缺陷、复测和发布证据 | 首板 L1、模块 L2、场景/长稳 L3 |
| 文档治理 | 本地 Markdown、飞书协作副本、附件哈希与历史归档 | 保持 PRD、决策、接口和验证结论一致 |

角色名称不等于具体人员名单。需要落实姓名时，在项目首页或协作规范中单独登记，不在本文猜测。

| `YAKA-OWN-005` | NFC 首发的卡片数据、业务动作和无网行为 | 只读；至少完成一个可演示且可验收的业务闭环 | M6 NFC 验收 |

| `YAKA-OWN-007` | 量化目标 | 先由工程测出启动、延迟、续航、温升、录音恢复和 OTA 基线，再由 Owner批准 | L3/发布门禁 |

## 7. 已关闭或被取代的旧事项

- ESP32-C6、LCD、TF/SDSPI、16 MiB Flash、电池 303260/650 mAh 的基本身份已经关闭，不再作为 Owner 输入缺口。
- Raynode/ESP-IDF 6.1 远程构建环境和新固件仓库已经建立，不再作为阻塞待办。
- 旧 2 MiB Flash、TF 无 CS、LCD 型号未知和旧 `projects/yaka/firmware` 基线已经废止。
- 原理图/PCB R1.6 静态复审已完成；当前工作从“继续理论审图”转向首板 Bring-up 和模块验证。
- LED2 极性与 CPL 坐标的工程 `HOLD` 已撤销；订单侧 DFM 留证仍是团队执行项，不再是 Owner 产品决策。
- 旧凭据内容已从在线入口移除；是否轮换外部账号由实际有效性另行处理，不在本文保存秘密值。
- 旧文档中的 G4/G5 未开始、固件仓库不存在、远程构建未接入等描述均已被后续证据取代。

## 8. 决策进入正式记录的规则

1. 本文用于“当前要决定什么”；飞书“决策与版本记录”用于保存已经生效的正式决定和版本影响。
2. Owner 回复某个 `YAKA-OWN-*` 后，更新本表状态，并把正式结论同步到决策记录和受影响的 PRD/接口/验证文档。
3. 被后续决定取代时保留 ID，写明取代关系，不静默改写历史。
4. 普通工程任务只进入固件 PRD、测试记录或缺陷库，不追加到 Owner 决策表。
