# HiYaKa PCA9557 首地址硬件／软件 I²C 对照

判读限制：ESP-IDF 硬件 I²C API 只返回整笔事务状态，不给出逐字节 ACK；软件路径记录地址、寄存器、数据三个 ACK。若需要硬件路径的首地址 ACK，必须结合此前独立 PARLIO 旁听证据，不能从 API 返回值推断 NACK 发生在哪个字节。

适用范围：旧 c0 板 GPIO10/11 上的 PCA9557 I²C。与新屏 GPIO6/7 和 172×320 配置无关。

隔离诊断，不属于产品固件。默认 CONFIG_HI_YAKA_PCA_STRAPS_FIXED=n，启动后只报告 HOLD，不操作 I²C。仅在 c0 板身份、功放隔离、温度正常，且 PN532 SET0/SET1 物理绑带固定并记录后，才允许把配置设为 y、重新构建和人工审计；旧板拆除 R73/R74 的悬空状态不满足门禁。不要把 COM7 的另一块 C6 板当 c0。

有效版本按硬件 I²C → 软件 I²C → 软件 I²C → 硬件 I²C（ABBA）执行。每阶段重新拥有 GPIO10/11，切换时销毁硬件设备与总线，软件模式仅以开漏拉低／释放、关闭内部上拉、依赖板上外部 4.7 kΩ 上拉。每阶段先验证 PA_EN=0 和 PCA 输出锁存 0x40、方向 0x38；每次空闲 20 ms 后写相同安全值两次，软件模式记录地址、寄存器、数据各 ACK，硬件模式记录 API 结果。随后双寄存器读回，并作 QMI8658A WHOAMI 正控与 0x55 空地址负控；任何门禁失败即停。末尾再次恢复并验证 PCA 安全态。

软件半周期请求值为 5 µs，GPIO 调用与时钟拉伸会增加实际周期，实际 SCL 频率未测。ABBA 最多定位硬件控制器路径是否为必要条件；若软件路径成功，还须按实际频率控制再试，不能宣称两路径同速。它也不能替代 U3 焊盘模拟波形。软件 SCL 拉伸超时会使该轮无效，不能把 STOP 调用视为总线已恢复。镜像 hash、板 MAC、PN532 绑带实体记录和用户目视需与原始 UART 一同归档。未在 c0 实板运行，M2 保持开放。
