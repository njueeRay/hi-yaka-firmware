# HiYaKa 首板麦克风无数据：软件 A/B 实板结果

> 2026-11-05；受控开发样机，L7 已拆，GPIO23/PA_EN 软件强制低，扬声器空置。以下是当前样机的 L1 诊断证据，不代表录音通过。原始串口记录保存在本地未入 Git 的 `.tmp/lab-audio-ab/`；文末给出镜像与日志校验值。当前板已恢复此前通过短时启动验证的 `hi-yaka-lab-headless` 镜像。

## 结论先行

**ESP32-C6 的 I²S 接收/DMA 可以读回已知数据；GPIO13 可以进入 I²S 采样链，但在当前 ES7210 录音条件下没有收到有效、主动驱动的数据。** 无论 ES7210 仅接收，还是完全跳过前置测试的正常双工路径，GPIO13 的弱下拉都使原始采样变成全 `0`，弱上拉使其变成全 `-1`；无上下拉时全 `0` 或全 `-1` 会随前序状态变化。两种固定码值都不是声音。MCU 端 MCLK/BCLK/WS 持续存在，GPIO13 在 20 ms 计数窗口内无上升沿。**置信度：高，仅限 MCU 端。**

不能据此判定 U12 芯片损坏或 R65 后走线开路。U12 焊盘供电、时钟与 SDOUT1 输出尚未直接测得；本轮 EasyEDA 连接器不在线，只能复用已封存的 R1.6 原理图/PCB 审计与前次活体回读，不把静态连接等同实物连通。

## 对照结果

| 实验 | 条件 | 实测 | 解释 |
|---|---|---|---|
| A 内部回环 | 16 kHz、双槽 16 位；GPIO1 同时接 I²S TX/RX，未驱动 GPIO13，PA 关闭 | `received=4096` 字、`matching=2048`、`PASS`；四次冷启动重复出现 | 排除主控 I²S 接收/DMA 完全失效；不能证明 U12 至 GPIO13 路径。 |
| B ES7210 单独 RX | 仅 RX、MIC1/MIC2、GPIO13；默认增益和 24 dB 各取 512 字 | 两次均 `ESP_OK`，512 字**全部为 `-1`**，峰值 1；调增益结果不变 | “非零”只是固定码值，不是有效声音；双工配对不是唯一原因。 |
| B 延时及弱上下拉 | RX 保持约 10 s；随后只改 GPIO13 内部弱下拉/弱上拉 | 10 s 后仍全 `-1`、`0x0B=0`；下拉后 512 字全 `0`，上拉后全 `-1` | MCU 数据输入受弱拉控制，强烈支持当前没有外部主动数据驱动；未区分 U12 输出未开启与中间通路断开。 |
| C 原双工，接在 A/B 后 | 与实验室标准双麦路径相同的 16 kHz、双槽 16 位；24 dB | 原始 I²S 为全 `0` 或全 `-1`；8 s 后 `0x0B=0`、GPIO13 无边沿 | 前置实验可能改变悬空电平，不能单用本行给硬件定性。 |
| C 独立原双工 | **完全跳过 A/B**，同一套 `BoxAudioCodec`；保持输入开启 25 s | 0.6 s 和 25.7 s 均全 `-1`、`0x0B=0`；下拉全 `0`、上拉全 `-1`。MCU 端 MCLK 约 4.1 MHz、BCLK 512 kHz、WS 16 kHz，GPIO13 0 上升沿/20 ms | 排除前置 A/B 残留为主要原因，也排除仅因等待 8–10 s 不够；仍不能证明时钟到达 U12 引脚。 |

本轮的 `0x0B=0` 按 ES7210 数据手册表示状态机处于 power-down；前次有屏幕、人工按 `ACT_B` 的实板记录在约 22.6 s 读到 `0x0B=2`（normal），**但那次 GPIO13 同样 0 边沿、原始数据全零**。两种启动/显示条件下的状态冲突仍未解释。手册的 `0x09/0x0A` 状态周期由 LRCK 计算，当前驱动写入 `0x30` 时，若 16 kHz LRCK 真正到达 U12，单阶段约 48 ms；因此本轮 25 s 不变不能简单归因于正常启动延时。[ES7210 数据手册，寄存器 0x09–0x0B](https://files.waveshare.com/wiki/common/ES7210_DS.pdf)。

## 交叉核对与剩余分支

R1.6 冻结设计与既有活体网表记录：U12/ES7210 的 SDOUT1 经 R65（51 Ω）接 ESP32-C6 GPIO13，MIC1/MIC2 接两颗实体麦；R65 电阻本体实测约 51 Ω，供电跳线 R63/R64 本体约 0 Ω。这些阻值**不证明**焊盘、过孔或 U12 至主控全路径连续。旧版已验收 S3 板使用同类 ES7210 双麦拓扑，证明功能方案可行，但不证明当前板装配正确。

[ES7210 数据手册的 QFN32 引脚表](https://files.waveshare.com/wiki/common/ES7210_DS.pdf)将 MCLK/SCLK/LRCK/SDOUT1 分别列为 **5/9/10/11 脚**；数字 I/O 电源 VDDP 为 6 脚，数字内核电源 VDDD 为 7 脚，模拟电源 VDDA/VDDM 为 22/23 脚。I²C `0x41` 应答只能说明控制接口可通信，不能替代上述每个电源脚、时钟脚和 11 脚输出测量。数据手册还将寄存器 `0x12` bit4 定义为 SDOUT1 三态控制；前次实板读回 `0x12=0`，使“软件显式置三态”的解释优先级下降，但不证明引脚实际输出。

按目前证据，后续优先级是：

1. **U12 是否真正进入可输出状态：**核对 6/7/22/23 脚实物供电及地、5/9/10 脚实物时钟；本轮 `0x0B=0` 与前次 `0x0B=2` 的差异也在此一并解释。
2. **U12 到 MCU 的实体数据路径：**同步看 U12.11、R65 两侧、GPIO13 的波形与静态连通。若 U12.11 有波形而 GPIO13 没有，定位 R65/焊盘/过孔/走线；若 U12.11 本身无波形，再查芯片工作条件和焊接。
3. **芯片/软件边界：**如供电、时钟和连通均符合手册，再比较 ES7210 不同配置及实装质量。此时才有依据判定 U12 本体或驱动时序。

当前没有示波器或逻辑分析仪、也无法让操作者进行新的物理测量，因此上述三支不能仅凭继续改 PCM 后处理来判定。麦克风功能保持 `FAIL`，M3/M4 录音里程碑不勾选。
