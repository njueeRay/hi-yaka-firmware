# HiYaKa PN532/C106 改线后的 HSU 实板验证

> 日期：2026-11-12（Asia/Shanghai）<br>
> 样机：当前 COM5/CH340K 样机；L7 已拆，用户确认测试时温度正常；具体样机编号未登记。<br>
> 物理绑带：`SET0=I0=0、SET1=I1=0`，用户确认改线后已让 PN532 完全断电重启。<br>
> 镜像：`diagnostics/nfc-hsu-rework/`，ESP-IDF 6.1 / `aliyun_raynode` 构建，应用区 `0x20000`，SHA-256 `9CEA08CDEB8C3B966BDEB1F60777E40F21A831A4F7717DA86401D2774D177841`；115200 baud 烧录并通过写后哈希校验。

## 结论

1. **HSU 诊断通过，置信度高。**最终镜像不执行 I²C 预扫描。它把 C106 唤醒前缀与第一条 `SAMConfiguration` 命令连续发送，然后读取芯片版本，再发 Type A 寻卡命令。日志收到 SAM、版本和一张实际标签的完整响应帧；寻卡响应的帧长与 DCS 校验符合 PN532 协议。标签 UID 不在此文档公开。
2. **首次上电启动通过，置信度高。**在同一镜像、完全断开 USB/电池/MASTER 后，串口守候程序捕获到首次上电的 SAM 和版本响应，而不是只抓到主控软复位。该冷启动窗口没有贴卡；实际读卡发生在相同镜像的另一运行窗口。因此“冷启动同窗口读卡”仍未单独记录。
3. **原设计的 I²C 问题仍未关闭。**当前原理图是 `I0=0、I1=1`，C106 因此选 SPI；本次临时 `00` 改线是 HSU。下一版或当前板若要使用 I²C，应设为物理 `I0=SET0=1、I1=SET1=0`，完全掉电后实测地址 `0x24`、初始化和读卡。HSU 结果不能代替 I²C 验收。
4. **不要把当前 HSU 绑带与带屏产品固件混用。**HSU 复用 GPIO10/11，而产品固件把两脚用于共享 I²C。恢复带屏实验镜像后出现 I²C 探测超时、PCA9557 写入重试和软复位；这足以说明该组合不适合继续做 LCD 验证，但不能仅凭日志量化总线电气冲突。当前板最终保留上述 HSU 诊断镜像。

## 关键实验对照

| 条件 | 直接观察 | 判断 |
|---|---|---|
| `00` 绑带，旧 A/B 程序先做 I²C 扫描再切 HSU，先读取版本 | 收到 `D5 03 32 01 06 07`，第二条命令无响应 | 证明 PN532 可经 HSU 返回版本；当时尚无读卡结论 |
| 保留旧 A/B 前置步骤，但先发 SAM，再读版本 | SAM 返回 `D5 15`，版本返回 `D5 03`；贴卡后 `InListPassiveTarget` 返回 `D5 4B` | 证明 C106 能进入正常读卡模式并驱动天线读到卡 |
| 删除 I²C 前置步骤，唤醒前缀和 SAM 分开发送 | SAM 与版本均无响应 | 该唤醒时序不成立；不能据此认为 I²C 前置必需 |
| 删除 I²C 前置步骤，把 `55 55 00 00 00` 与 `00 00 FF ... D4 14 ...` 连续发送 | SAM、版本均应答；贴卡后收到一张 Type A 卡的有效响应 | 纯 HSU 链路成立，I²C 前置步骤可删除 |
| 完全断电后，同一纯 HSU 镜像首次上电 | 守候 COM5 的采集程序在未主动复位主控的条件下捕获 SAM 与版本响应 | 冷启动初始化成立 |

原厂 C106 应用说明规定上电 LowVbat 模式以及先用 `SAMConfiguration` normal 模式进入正常运行；本次命令顺序与连续唤醒帧的修正基于该说明，并由上述 A/B 实测支持。最初“版本先发”失败不能简单归因于卡片或天线。

## 下一步与边界

- 当前板完全断电后把物理绑带改为 `I0=1、I1=0`，再运行 I²C 诊断。先看 `0x24` 地址应答，再看版本、SAM 和实际标签；三层不得合并判定。
- I²C 模式稳定后再运行带屏实验固件，测 LCD 面板电源与复位静态电平，继续定位“背光有、画面无”。不要在 `00` 绑带下用带屏固件的 I²C 错误作为 LCD 根因。
- 本目录程序是单模块诊断，不是多外设产品驱动。尚未验证无卡超时、反复刷卡、与其它外设并发、长稳或发布门槛；`HIYAKA-NFC-INC-001` 仍为打开状态。

## 模式脚悬空与下一版绑带决定（2026-11-12）

用户已断开 SET0、SET1 的外部绑带，当前两脚实际电平未测得。**悬空不代表任何确定模式，也不能据此运行 I²C 验收。**PN532/C1 数据手册把 I0/I1 定义为输入，给出 VIH/VIL 门限与输入漏电，未规定悬空默认值；C106 固件在上电时采样两脚。悬空时芯片可能在 HSU、SPI、I²C 或保留组合间不稳定地变化，测试现象不能推断固定绑带的行为。

对目标硬件，采用 **I0/SET0 经配置电阻接 PN532 的 DVDD，I1/SET1 经配置电阻接 GND** 的设计方案。两份 NXP C106 专用资料（AN10609_3 与 AN10688）都明确列出物理 `I0=1、I1=0` 为 I²C。必须同时记录证据冲突：较新的 PN532/C1 通用数据手册把内部 `selif[1:0]=10` 列为 I²C，又写明 I0/I1 分别复制到 `selif[0]`/`selif[1]`，按字面推算与 C106 专用物理绑带表相反。当前实板仅已验证 `00` 的 HSU；**未验证 `10` 的 I²C，不能把下一版的 I²C 功能标为已通过**。下一版可先按 C106 专用表布局，但须保留可反向改绑的电阻位，并在首件用 `0x24` 应答、版本读取和实际寻卡完成最小验收。

当前 PCB 活体回读：U13.16=`SET0`、U13.17=`SET1`；R73 的 2 号焊盘接 `SET0`、1 号焊盘接 GND；R74 的 1 号焊盘接 `SET1`、2 号焊盘接 `SYS_3V3`。SET0/SET1 无过孔。若返修本板，优先使用电阻焊盘而非 U13 密脚；先确认用户切断的走线仍使信号焊盘与 U13 连通。R74 原有高电位是 `SYS_3V3`，而数据手册规定 I0/I1 高电平以 **DVDD** 为基准；下一版上拉电源应选择 PN532 的 DVDD，而不是未经电平域复核便沿用 `SYS_3V3`。当前 U13.39/DVDD 的 PCB 网络名为 `VREF`，该节点曾实测约 3 V，但下一版仍需在 EDA 中核对供电时序和具体连接。

仅作为当前板的返修候选：若 R73/R74 已移除，且两颗电阻的信号焊盘到 U13 仍连续，可在完全断电状态下让 R74.1（SET1）经绝缘细线接 R73.1（GND），再让 R73.2（SET0）经独立绝缘细线接 C108.2（VREF/DVDD）。两线不必在 U13 密脚处交叉；施工前后均需查短路和实际电平。若信号焊盘到 U13 的走线也被切断，则本方案不适用。用户目前不方便显微返修，因此不把此候选视为已执行方案。
