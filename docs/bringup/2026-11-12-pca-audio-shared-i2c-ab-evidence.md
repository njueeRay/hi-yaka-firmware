# HiYaKa：PCA9557 与麦克风共享 I²C 的同板对照证据

> 日期：2026-11-12。范围：已拆除功放 L7、屏幕背光飞线有效、PN532 SET0/SET1 电阻已拆的当前样机。本文记录实验边界；麦克风问题仍按 `HIYAKA-AUDIO-INC-001` 跟踪，LCD 稳定性仍按现有显示问题跟踪。

## 要判断的两件事

1. 屏幕刷新对 PCA9557 的频繁访问，是否是 I²C 无应答与音频失效的必要条件？
2. 若 I²C 暂时正常且音频确实完成初始化，ES7210 的数据是否到达 ESP32-C6 GPIO13？

这两件事必须分开。PCA9557 和 ES7210 共用 SDA/SCL，但冻结网表中 ES7210 的电源不是由 PCA9557 控制；PCA9557 失联可以干扰 ES7210 寄存器配置或让固件跳过初始化，却不能直接证明 SDOUT1 走线或芯片输出失效。

## 固定的硬件与软件事实

- U3/PCA9557 地址脚 A0 经 R8（10 kΩ）上拉到 SYS_3V3，预期地址 `0x19`；用户先前对地实测 R8.1 固定 3.3 V、R8.2 在 0 与 3.3 V 间变化；本轮同板、恢复横屏镜像后重新实测 R8 靠 U3/A0 端**稳定 3.3 V**，同时 `0x19` 地址探测全应答。此前跳变保留为历史读数，但不能当成当前状态。
- ES8311 地址为 `0x18`，所以 PCA9557 A0 偶发低电平可能造成地址冲突；目前还没有抓到同一时刻的器件身份和 A0 波形，不能认定冲突已经发生。
- 本次样机的 PN532 模式电阻 R73/R74 均已拆除，SET0/SET1 悬空。这是与此前稳定日志不同的另一项硬件条件；其接口模式不能按 I²C 或 HSU 已确定处理，也不能排除它对共享总线造成干扰。
- U12/ES7210 地址 `0x41`；U12.11/SDOUT1 经 R65（51 Ω）到 ESP32-C6 GPIO13。MCU 端 MCLK/BCLK/WS 曾测得时钟，GPIO13 曾测得零边沿；U12 引脚处时钟、SDOUT1 及 R65 两侧波形尚未测量。
- 当前固件 `InitializeAudio()` 原先要求 ES8311、ES7210 两者均即时应答，否则整段音频初始化跳过；这是一项会遮蔽输入诊断的启动门槛。提交 `5fa5b35` 将**专用** `hi-yaka-lab-audio-ab` 的仅输入实验移到该门槛之前，产品构建的初始化策略不变。

### G 实验的关键计数

| 项目 | 首轮 100 kHz | 25 kHz（两轮一致） | 末轮 100 kHz |
|---|---:|---:|---:|
| PCA9557 单独连续读 `0x01` | 成功 1/128 | 0/128 | 0/128 |
| ES7210 单独连续读 `0x0B` | 0/128 | 0/128 | 0/128 |
| PCA9557 交替访问中的安全写 `0x01=0x40` | 128/128 | 128/128 | 128/128 |
| ES7210 交替访问中的重复起始读 `0x0B` | 128/128 | 128/128 | 128/128 |
| QMI8658A 交替访问中的读 `0x00` | 128/128 | 128/128 | 128/128 |
| `0x19`、`0x41`、`0x18` 地址探测 | 各 16/16 | 各 16/16 | 各 16/16 |
| ES7210 分笔写寄存器指针、再读数据 | 两笔均 0/16 | 两笔均 16/16 | 两笔均 0/16 |

所有不成功的寄存器事务本轮均返回 `ESP_ERR_INVALID_RESPONSE`（NACK），没有超时。空闲时 SDA、SCL 的 GPIO 读数均为高。首版诊断的 5 ms 延时低于本固件的 tick 粒度，实际未形成预期等待；上表使用修正后的 10 ms 版本。首版数据不用于速率判断。独立诊断**没有配置 ES7210 或采集 PCM**，因此本表只能定位控制总线访问的条件依赖，不能证明麦克风音频数据已经恢复。分笔读也不构成产品代码修复方案，因为两颗器件手册都支持重复起始读。`i2c_master_probe` 使用总线默认速率，其 16/16 不作为 25/100 kHz 性能对照。

## 当前判断

- **高置信度：**当前样机存在独立于屏幕刷新流量的 I²C 不稳定；它已经实际造成音频初始化被跳过。
- **高置信度：**启动阶段全地址扫描并非必要原因；跳过扫描后，PCA9557 与 ES7210 仍分别出现控制读写失败。内部 I²S 接收/DMA 回环通过。
- **高置信度：**最小程序中 `0x19/0x41` 地址应答和 PCA9557 安全写入稳定，但连续寄存器读与交替访问表现截然不同；本轮不支持“PCA9557/ES7210 固定失联”或“降到 25 kHz 可普遍修复”的结论。
- **中置信度：**当前失败以事务 NACK 为主；一次 PCA9557 重试耗尽时 GPIO10/SDA 与 GPIO11/SCL 均读为高电平，最小程序空闲读数也为高。静态高电平不等于上升沿、上拉阻值或波形合格。需要区分事务编码、前序操作、器件状态和实际电气波形。
- **低置信度（当前状态）：**R8/A0 地址绑带漂移导致 PCA9557 与 ES8311 `0x18` 冲突。先前有跳变读数，但本轮 A0 稳定 3.3 V、`0x19` 地址探测全应答，当前证据更支持继续查事务形状/时序；不能排除另一上电状态或接触条件下复现。
- **未知：**PN532 两个模式脚悬空是否在本次实验中干扰 SDA/SCL；不能把当前 I²C 异常全部归因于 R8 或固件顺序。
- **未知：**在当前样机上 ES7210 成功初始化时，U12.11 是否输出、R65 两侧是否有数据、GPIO13 是否接收到数据。本轮三组同板镜像未进入有效的标准音频采集，不将其写成“麦克风仍为零”的新证据。

## 下一步与关闭条件

暂停重复烧录相同音频镜像。当前无需 PN532 返修也能继续软件分析：下一轮应在同板上对照 ESP-IDF I²C 事务序列与设备驱动调用顺序，先将 PCA9557/ES7210 的寄存器读写稳定性与地址探测区分，再让 ES7210 完成初始化和 PCM 接收。只在读写稳定且 `0x0B` 表示正常工作后，才用原始 PCM、GPIO13 边沿判断麦克风数据链路。若此时仍无数据，再由维修台测 U12.11、R65 两侧及芯片脚电源/时钟。硬件归因仍要记录 PN532 模式脚悬空这一混杂因素；R8/A0 本轮稳定 3.3 V，当前不是首要分支。LCD 需要持续运行和无重试/无像素发送错误，不能以单次横屏显示关闭稳定性问题。

实验结束后已烧回此前由用户目视确认横屏正常的 GPIO 显示镜像（SHA-256 `4D436FF4867AD641ECE6ACCAFD642F719561378E76FFE1C9EC5CC6823FFF287A`），设备端写入哈希校验通过。首次恢复的 40 秒日志确认 `hi-yaka-lab-lcd-gpio` 启动一次、五次纯色 API 完成；同时有 305 条 PCA9557 写重试、13 次重试耗尽和 12 次 LCD 像素发送失败，用户目视为**仅有背光、无任何颜色或文字**。保持同一镜像、同一接线，仅再次复位，用户看到颜色或文字、温度正常；随后确认画面仍显示，文字沿长边横向排列、无雪花带。第二次 40 秒日志仍有 318 条重试、19 次耗尽和 15 次像素发送失败。这证明显示的当次成败具有间歇性，排除“镜像未写入”为首次黑屏的解释；并不证明 PCA9557 是唯一硬件根因。**当前 LCD 稳定性仍为 FAIL。**

G 实验后再次烧回**同一横屏镜像**，115200 baud 写后哈希校验通过。复位后的约 38 秒日志显示同一 `hi-yaka-lab-lcd-gpio` 镜像启动、五色 API 依次完成，但仍有 298 条 PCA9557 首次写 NACK 重试、13 次三次写入全部失败及 12 次 LCD 像素发送失败。用户随后确认当前**横向画面正常、温度正常、R8 的 A0 侧稳定 3.3 V**。因此此轮“可见画面”与“控制事务失败”并存，不能把可见画面等同于显示稳定验收。此次恢复没有更换引导程序、分区表或用户资源。
