# HiYaKa 证据等级与里程碑矩阵

## 1. 证据等级

| 等级 | 证据来源 | 能证明什么 | 不能替代什么 |
|---|---|---|---|
| L0 | 静态审计、host tests、可复现构建、哈希与 CI | 软件合同、构建和产物可追溯 | 目标板启动和任何物理功能 |
| L1 | 目标板电源、启动、总线、芯片身份和基础回读 | 板级接口已进入功能验证 | 用户功能、异常恢复和稳定性 |
| L2 | 实板完整功能链、重复性、故障注入与恢复 | 单个功能满足已定义验收 | 整机长稳、功耗、温升和发布结论 |
| L3 | 整机压力、长稳、功耗、温升、声学、OTA/回滚 | 可作为发布候选判断输入 | 未覆盖批次、场景或生产流程的泛化结论 |

编译通过不能升级成 L1；地址 ACK 不能升级成 L2；一次完整功能成功不能升级成 L3。

## 2. M1–M7 关闭矩阵

| 里程碑 | 业务可理解目标 | 最低证据 | 必需模块记录 | 关闭前仍需人工复核 |
|---|---|---:|---|---|
| M1 | 板子能安全上电、下载、启动并识别基础总线 | L1 | `power`、`flash`、`i2c`、`pca9557` | 电源异常、复位差异、装配缺失是否解释清楚 |
| M2 | 屏幕、按键、电量和反馈形成可见可操作闭环 | L2 | `display`、`input`、`feedback`、`battery` | 交互定义、ADC 标定、低电和供电扰动 |
| M3 | 双麦、播放参考和扬声器链路稳定 | L2 | `audio` | 通道映射、爆音、削波、丢帧和并发资源 |
| M4 | 本地录音可靠保存并能从异常中恢复 | L2 | `storage`，并引用 `audio` 通过记录 | 多类卡、硬切电、长录音、恢复和数据完整性 |
| M5 | 配网与 AI 对话主路径可用且可恢复 | L2 | `network`，并引用 `audio`/`input` 通过记录 | 弱网、断网、打断、录音互斥和隐私状态 |
| M6 | NFC、IMU 和辅助反馈可控地加入主流程 | L2 | `nfc`、`imu`、必要时 `feedback` | 超时、轴向、标签兼容和业务范围 |
| M7 | OTA、并发长稳和发布证据闭环 | L3 | `ota`、`long_run`，并引用 M1–M6 结果 | 未关闭 P0/P1、生产签名、批次和发布回滚计划 |

## 3. 场景到证据目录

| 场景 | 主记录 | 建议原始证据 |
|---|---|---|
| 安全默认态 | `power`、`pca9557` | 上电视频、限流记录、寄存器/总线捕获 |
| 外设缺失或 NACK | `i2c` 与对应模块 | 注入方法、完整日志、恢复时间线 |
| 随机硬切电 | `storage`、`ota` | 切电时点、恢复前后文件/版本哈希 |
| 弱网与断网 | `network` | 网络条件、状态机日志、资源趋势 |
| 长录音 | `storage`、`audio` | 时长、丢帧、文件哈希、内存与队列趋势 |
| OTA 与回滚 | `ota` | 包身份、槽位、启动次数、确认/回滚日志 |

## 4. 结论状态

- `GO`：所需证据等级已满足且无未关闭 P0/P1；
- `CONDITIONAL GO`：无 P0，P1 有清晰边界、Owner、截止条件和补测计划；
- `NO-GO`：存在 P0、未解释差异、关键检查缺失或证据身份不一致；
- `UNKNOWN`：没有足够证据。硬件尚未到位时，真实功能状态必须保留为此状态。
