# HiYaKa 首板上电与基础验证手册

> 目标：取得 M1 所需的首批 L1 证据
> 适用硬件：ChatChat HiYaKa / R1.6
> 禁止事项：在限流值、接线和硬件 revision 未确认时直接上电；把“能下载”写成“整板功能通过”

> **P0 前置门禁（2026-11-04）：**两块样机已在 U11/BOOST 支路复现快速异常发热。任何同批样机必须先完成[专项复盘与恢复方案](../hardware/HIYAKA_U11_THERMAL_INCIDENT_AND_RECOVERY.md)定义的物理隔离/返修，并证明 `PA_EN/CTRL` 不会在复位期间开启错误功率支路。原手册不能直接用于未返修板。

## 1. 人员与设备

至少准备：可调限流电源、数字万用表、示波器或逻辑分析仪、USB-UART/板载 CH340K、可靠 USB 线、ESD 防护、热成像仪或非接触测温手段、带 SHA-256 的候选固件包，以及实验室证据目录。

限流电源的电压和电流上限不能由本文猜测。测试负责人必须从已批准的硬件上电计划、器件限制和硬件 Owner 结论取得数值，并原样写入 `measurements/power.csv`。没有获批值时，状态为 `BLOCKED`，不得试探性加电。

## 2. 上电前冻结现场

1. 为样机分配唯一编号，记录硬件 revision、PCB/SMT 批次和可见返修；
2. 对 PCB 正反面、连接器方向、极性器件和焊接异常拍照；
3. 记录 U11、L7、D10、C60 和 `PA_EN` 的实装/返修状态；未隔离 U11 CTRL 且未更换错误 L7 时立即停止；
4. 断电测量关键电源轨对地阻值，并与硬件负责人提供的正常范围或同批良品比较；
5. 确认 MASTER_SW 状态、USB 和外部电源不会形成未批准的反向供电；
6. 核对候选固件 SHA、上游 SHA、容器 digest 和合并镜像 SHA-256；
7. 运行证据工具 `init`，生成不可混淆的 run 目录。

任一极性、短路、反向供电或样机身份存在疑问时，停止在断电阶段。

## 3. 分级限流上电

1. 保持 MASTER_SW 关闭，连接地线和测量探头；
2. 设定获批电压与首级限流，记录设定值、仪表型号和校准状态；
3. 打开 MASTER_SW，连续观察电流、3.3 V 轨、复位信号和异常发热；
4. 按批准计划逐级提高限流，不跨级；每一级保存时间戳、电流和关键电压；
5. 至少执行三次完整冷启动和一次复位，保存电流曲线及串口原始日志；
6. 上电后仍保持 PA、LCD 背光、RGB、五灯链和马达关闭，先验证基础安全态；当前样机 PA 必须已物理禁用，而不是仅依赖固件拉低 GPIO23。

立即断电条件：持续顶住限流、关键轨超出批准范围、U11/L7/D10/C60 任一处快速升温、异常发热/异味/声音、复位快速循环、背光或马达在安全态前动作、无法解释的电流突变。断电后记录实际现象并建立缺陷 ID，不以重复上电代替分析。

## 4. 下载与串口链

1. 记录 CH340K/串口设备枚举、端口名和主机系统；
2. 在不烧录前读取芯片身份、MAC/eFuse 摘要和 Flash JEDEC 信息，避免先覆盖现场；
3. 核对目标为 ESP32-C6、Flash 为 16 MiB DIO、PSRAM 禁用；
4. 使用 CI 归档的 `merged-binary.bin` 烧录，不使用来源不明的本地临时文件；
5. 保存烧录命令、工具版本、完整输出和烧录后读回/校验结果；
6. 保存三次冷启动日志，必须包含复位原因、固件源 SHA、Flash ID/容量、分区和内部堆诊断。

通过条件：下载链可重复，读回/校验一致，启动日志与候选 provenance 匹配，且无无法解释的重启循环。此结论只关闭 `flash` 的 L1，不代表外设通过。

## 5. I²C 基础验证

共享 I²C0 使用 GPIO10 SDA、GPIO11 SCL，首板仅以 100 kHz 开始。装配目标地址：

| 地址 | 器件 | 允许的首板结论 |
|---:|---|---|
| `0x18` | ES8311 | 地址响应存在；功能仍待音频验证 |
| `0x19` | PCA9557 | 地址响应及安全寄存器回读 |
| `0x24` | PN532 | 地址响应存在；标签业务仍待验证 |
| `0x41` | ES7210 | 地址响应存在；通道映射仍待音频验证 |
| `0x6B` | QMI8658A | R90 将 SA0 拉低；地址响应及芯片 ID 待模块验证 |

操作要求：

1. 先保存 SDA/SCL 空闲电平和上拉情况；
2. 保存每个固定地址的 ACK/NACK、超时和重试次数；
3. 用逻辑分析仪记录至少一次完整探测事务；
4. 对缺失地址先核对装配、供电和总线波形，不以无限重试掩盖故障；
5. 验证单器件缺失或 NACK 时系统进入可诊断降级态，而非重启循环。

地址全部出现只证明总线基础可用，不能证明 codec、NFC 或 IMU 功能通过。

## 6. PCA9557 安全态

PCA9557 地址为 `0x19`。必须在 LCD、马达和相关驱动初始化前验证以下顺序：

1. 写 Output Port=`0x40`，先锁存安全输出；
2. 写 Configuration=`0x38`，仅 IO0/1/2/6/7 成为输出；
3. 回读 Output 和 Configuration；
4. 确认 LCD 背光关闭、LCD_CS 未选中、马达关闭；
5. 注入一次 NACK 或回读不一致，确认固件报告明确错误并阻止后续危险动作。

通过条件：逻辑分析仪和寄存器日志共同证明写入顺序、值和回读一致；物理输出处于安全态。只有串口中打印“成功”但没有总线/输出证据，不足以判定通过。

## 7. M1 关口

M1 的四个必需模块为 `power`、`flash`、`i2c`、`pca9557`。运行：

```powershell
python scripts/hi_yaka_evidence.py validate --run <run目录> `
  --require-module power `
  --require-module flash `
  --require-module i2c `
  --require-module pca9557
```

允许关闭 M1 的条件：四项记录均非 `NOT_RUN`，其中任何 `FAIL/BLOCKED` 均已按项目发布规则处理；原始证据可打开；固件和样机身份一致；不存在未解释的电源、复位或接口差异；`HIYAKA-HW-INC-001` 的现板隔离条件已经满足。工具校验成功不是自动 `GO`。
