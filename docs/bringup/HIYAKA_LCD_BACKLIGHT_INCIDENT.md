# 专项问题分析：HiYaKa 显示屏完全无背光

> 问题编号：`HIYAKA-LCD-INC-001`<br>
> 级别：`P1`<br>
> 首次确认：2026-11-04<br>
> 影响范围：HiYaKa R1.6 首批样机；当前实测为已拆 L7 的开发样机<br>
> 当前状态：背光硬件控制网缺少上拉，显示功能 `FAIL`，待返修与画面复验

## 1. 结论

- **已确认：**屏幕始终完全无背光；固件写入 PCA9557 的背光输出位后可读回配置，但 R85 两端均约 0 V，Q10 栅极没有被拉高。
- **已确认的根因：**PCA9557 的 IO0 是开漏输出，只能下拉或释放；当前 `LCD_BL` 控制网没有上拉，Q10 栅极却有 R86 下拉。因此固件把 IO0 写为 1 也不能驱动背光开关导通。此根因对“无背光”具有**高置信度**。
- **未知：**ST7789 画面、FPC 接触及背光 LED 本体是否还有独立故障。该屏没有可用的控制器数据读回链路，I²C 扩展器应答不等于 LCD 已应答。
- **决策：**当前样机可在功放隔离条件下继续非显示模块测试（`CONDITIONAL GO`）；显示功能与整机发布 `NO-GO`，M2 显示验收不关闭。

## 2. 现象

操作者在较暗环境确认屏幕与关机时一样黑，没有微光或画面。固件已执行 ST7789 写入和约 7 秒后的背光 ON 测试；PCA9557 地址 `0x19` 应答，IO0 输出锁存/方向寄存器可读回。MASTER ON 时，R85 靠 PCA9557 侧和靠 Q10 栅极侧对地均接近 0 V；R84 两端均约 1.6–1.7 V，对 10 Ω 串阻而言压差接近零。上述测量来自同一开发样机的首板诊断，尚未对全批量逐板验证。

## 3. 排查分析

设计链路为 `SYS_3V3 → FPC1 LEDA(5) → 背光 LED → LEDK(6) → R84(10 Ω) → Q10 → GND`；Q10 栅极由 `PCA9557 IO0/LCD_BL → R85(1 kΩ)` 控制，并由 R86(10 kΩ) 下拉。原理图和 PCB 网表均未见 `LCD_BL` 上拉。NXP 原厂手册明确 IO0 为开漏；输出高时是高阻，不能向 R85/Q10 栅极提供高电平。R85 双端约 0 V 与这一设计相符。R84 两端近似等电位也支持背光支路没有正常电流。

这能定位**背光控制缺陷**，不能同时定位屏内 LED、FPC 排线或 ST7789 像素数据链。先前“LCD 有应答”的说法应限定为 PCA9557 的 I²C 寄存器应答；ST7789 写入 API 无报错不是 LCD 控制器回包。固件初始化序列即使修改，也无法在缺少硬件上拉的 IO0 上产生高电平。

## 4. 解决方法

1. **当前样机：**无需为了排查其它外设而立即动 FPC。若维修台具备安全返修条件，可在完全断电后以约 2.2 kΩ 电阻将 R85 的 PCA9557 侧上拉到 `SYS_3V3`，再上电核对 Q10 栅压、R84 压降、背光及全屏色块。此为**待验证的临时返修方案**，不是已完成修复；当前操作者此前明确表示不便飞线，不能将其当成已执行步骤。
2. **下一版永久修复：**优先改由经完整引脚资源核对的 PCA9557 推挽输出控制 Q10 栅极，保留外部默认下拉，确保上电和固件未启动时背光关闭；同步更新原理图、PCB、固件安全态与 DFM，并实测启停电平和屏幕亮度。若继续使用 IO0，则必须设计合适的上拉和上电默认态，按背光电流与功耗重新核算。
3. **不能采用：**不可用裸导线把 IO0 直接短到 3.3 V，固件安全初始化可能主动拉低 IO0；不可把扩展器读回或无报错写屏当作画面通过；不可直接触碰 0.5 mm FPC 相邻脚进行盲测。

## 5. 验证与关闭标准

- [ ] 返修或下一版板上，背光 OFF/ON 两态的 IO0、R85、Q10 栅极和 R84 压降均按设计实测，冷启动默认 OFF；
- [ ] 亮屏后显示全屏红、绿、蓝、白、黑及文字图案，确认 FPC、ST7789 数据、方向与颜色；
- [ ] 重复冷启动、按键、TF/NFC/I²C 并发与持续亮屏，未复现背光失控或新的总线错误；
- [ ] 记录原始测量、照片/视频、固件 SHA、样机编号和返修位置，重新评估 M2 与发布门禁。
