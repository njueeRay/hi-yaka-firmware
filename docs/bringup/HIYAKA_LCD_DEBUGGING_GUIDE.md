# HiYaKa LCD 调试方法、已证结论与发布门禁

更新时间：2026-11-27

适用对象：ChatChat HiYaKa c0 样机、ESP32-C6，以及本轮已实测的 LCD 控制链与实验屏配置
当前结论：GPIO Fast 是产品候选基线；PARLIO 在当前硬件与固件组合下不可验收；PCA9557／共享 I²C 异常仍未关闭；M2 屏幕验收未完成。

本文是面向后续研发的独立调试指南。它解释“为什么”，也给出现场执行顺序。事故全过程与逐次原始记录保留在 [LCD 背光与显示专项](HIYAKA_LCD_BACKLIGHT_INCIDENT.md)；本文不替代事故证据，也不把一次可见画面升级为稳定验收。

## 一、先把 LCD 链路拆成五层

排查 LCD 时不得把“屏幕亮了”“驱动 API 返回成功”“出现过像素”混成同一结论。HiYaKa 的显示链至少包含五层：

```text
供电与背光
  → 复位、片选、数据/命令控制（PCA9557 / I²C）
  → 命令和像素串行数据（GPIO6 / GPIO7）
  → ST7789 窗口、方向、偏移与 GRAM
  → LVGL 布局、dirty rectangle 和恢复策略
```

每层的通过证据不同：

| 层级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 背光亮 | 背光供电和至少部分开关链有效 | LCD 控制器已初始化、像素链有效 |
| 出现花屏或随机色块 | 屏幕收到了足以改变 GRAM 的电气活动 | 位序、CS、D/C、窗口和一帧数据正确 |
| API / DMA 返回 `ESP_OK` | 主控驱动接受并完成了提交 | 只写 LCD 实际显示正确 |
| 一次画面完整 | 该次事务组合可工作 | 冷启动、持续刷新和错误恢复稳定 |
| 日志与目视持续通过 | 当前样机和镜像在规定窗口内可用 | 下一版硬件、另一块屏或另一镜像自动等价 |

## 二、冻结基线后再做单变量实验

每轮实验必须同时冻结：

- 板卡身份与 BASE MAC；本轮 c0 为 `98:a3:16:be:d6:c0`；
- 屏幕型号、分辨率、方向、偏移和 FPC 接线；
- 功放隔离状态、温度和供电方式；
- PN532 模式绑带状态；当前 c0 的 R73/R74 已拆、SET0/SET1 悬空，是共享 I²C 归因的混杂变量；
- 构建环境、配置名、应用镜像 SHA-256、烧录偏移和串口速率；
- 五色、时间、动画、菜单和刷新区域等视觉负载；
- 用户观察的准确时间窗，以及对应的串口日志。

故障候选测试结束后必须恢复已验证基线，并完成写后哈希、启动日志和实屏三项复核。若只完成烧录哈希，不得写成“产品已恢复运行”。

## 三、PARLIO：花屏不等于链路接近成功

### 3.1 早期“只有背光”的两个确定性软件错误

早期 PARLIO 候选存在两个已证实现错误：

1. `transport_buffer` 只在 SPI DMA 配置下分配，PARLIO 像素传输拿到空缓冲并返回错误；
2. GPIO 命令与 PARLIO 像素切换时重复调用 `gpio_config()`，引脚所有权和 GPIO Matrix 恢复方式不正确。

修复后，软件日志可以完成整屏和菜单刷新，但实屏出现竖向彩条、短线、白色残留和局部色块，最后变为空屏。这个结果只证明 SCLK/MOSI 有活动并被面板部分解释，不证明协议正确。

### 3.2 微雪经验中真正有效的三个条件

微雪 ESP32-C6-LCD-1.47 的实板对照证明：

1. `RAMWR` 之后必须明确把 D/C 切回数据态；否则像素可能被面板当作命令；
2. 位打包顺序必须经非同色图案和文字实屏核对，不能从 API 成功反推；
3. 微雪板的 LCD CS 直连 MCU GPIO14，可由 PARLIO `valid` 与像素时钟硬件同步。

前两项可以移植为固件经验，第三项是硬件前提。HiYaKa 当前 LCD CS、D/C、RST 经 PCA9557，PARLIO 只能直接控制 GPIO6/7 的时钟与数据，不能把 PCA9557 输出配置成 `valid_gpio_num`。

```text
微雪：PARLIO ──硬件同步── CS + SCLK + MOSI

HiYaKa：PARLIO ─────────── SCLK + MOSI
        I²C → PCA9557 ─── CS + D/C + RST
```

软件可以保证“先通过 I²C 改 CS，再启动 PARLIO”，却不能保证 CS 与第一个、最后一个有效时钟边沿处于同一硬件时基。主控 pad 旁听实验还在正式命令窗口前看到了额外 SCLK 边沿，进一步说明所有权切换和有效窗口并不等价于微雪直连方案。

### 3.3 已完成的 HiYaKa PARLIO 矩阵

| 候选 | 实屏结果 | 判定 |
|---|---|---|
| 1-bit LSB、10 MHz | 竖向彩条、断线、残留，最终空屏 | 像素活动存在，协议失败 |
| 4-bit 全链编码 | 仅背光 | 命令与像素同时变化，反例保留 |
| GPIO 命令＋4-bit PARLIO 像素 | 仅背光 | 排除“命令改走 PARLIO”是唯一原因 |
| 4-bit 像素＋软件 CS 保护窗口 | 仅背光 | 软件保护不能替代硬件 `valid` |
| 1-bit MSB＋软件 CS 保护窗口 | 仅背光 | 位序和保护窗口组合仍失败 |

这些候选均能在软件侧完成传输，部分窗口内 `pca_exhausted=0`、`refresh_failed=0`，但只写 LCD 没有画面应答，因此软件计时不能作为有效画面性能。

**停止条件：**现阶段不再排列 PARLIO 位序、数据宽度或软件 CS 组合。继续尝试必须新增能区分根因的证据，例如 FPC 端逻辑分析仪／示波器波形，或下一版硬件把 CS 直连 MCU。没有新判别力的参数排列属于过度优化。

## 四、当前传输基线和性能边界

统一测试画面为五色整屏、`HH:MM:SS.mmm`、48×48 动画、模式标签与 LCD/PCA 计数。当前 c0 屏一次 320×200 RGB565 整屏为 128,000 B。

| 模式 | 五次整屏平均 | 菜单局刷典型值 | 实屏状态 | 产品适用性 |
|---|---:|---:|---|---|
| GPIO Slow | 4,254.757 ms | 约 148–151 ms | 日志通过；本轮镜像仍需独立目视 | 仅诊断 |
| GPIO Fast | 803.684 ms | 约 29.8–30.5 ms | 多轮五色、横屏菜单和动画通过 | 当前产品候选基线 |
| PARLIO 1-bit 10 MHz | 140.692 ms | 约 7.8–8.3 ms | 花屏／空屏 | 不可用；数字仅为 DMA 提交时间 |
| SPI2 DMA 12 MHz | 122.795 ms | 约 6.47–6.58 ms | API 与日志通过；实屏待补 | 仅性能上限诊断，和 TF 争用唯一 SPI2 |

GPIO Fast 不是标准 SPI 外设模式，而是直接写 ESP32-C6 GPIO 寄存器，以 bit7→bit0 的顺序产生数据和时钟。它比普通 `gpio_set_level()` 快约 5.29 倍；当前约 0.804 秒整屏不适合高帧率视频，但约 30 ms 的局部菜单刷新已达到当前状态界面可用水平。最终产品验收仍需规定页面切换、局刷、CPU 占用和长稳门槛，不能只凭演示动画主观判断。

## 五、PCA FIRST、EXH 和 DRAW FAIL 的准确含义

产品固件每次写 PCA9557 寄存器最多立即、静默尝试五次：

```text
第 1 次失败 → PCA FIRST +1
第 2～5 次任一次成功 → 本次控制操作最终成功
五次全部失败 → PCA EXH +1
LCD 命令、像素或 CS 释放因此失败 → DRAW FAIL +1
```

- `PCA FIRST` 是“PCA9557 寄存器写第一次尝试失败”的累计数，不是帧数或肉眼卡顿次数；
- `PCA EXH` 是五次全部失败；
- `DRAW FAIL` / `refresh_failed` 是某个 LCD 刷新事务最终失败。

最新 GPIO Fast 恢复复验约 85 秒记录 `pca_first=1970`、`pca_exhausted=1`、`refresh_failed=1`。之后的一次性全屏补画恢复了最终画面。这证明五次重试和补画是有效容错，也证明底层故障没有消失。

隔离实验后的恢复门禁也已完成：实板读回完整 131,072 B 启动区并与实验前备份哈希一致；恢复后的 45 秒冷启动确认 GPIO Fast 五色每次约 803.6–803.7 ms、进入 `BRINGUP READY`，窗口末 `pca_first=978`、`pca_exhausted=0`、`refresh_failed=0`。但同一启动中仍出现一次 PCA 背光锁存读回 `ESP_ERR_INVALID_RESPONSE`；约 11 分钟后的运行窗口中首败已累计超过 1.6 万次。恢复成功与控制链修复是两个不同结论。

### 5.1 最新共享 I²C 隔离结果

最小程序关闭 LCD、音频业务、马达、TF 和 NFC 命令，在 `100 kHz → 25 kHz → 25 kHz → 100 kHz` 四阶段各执行 128 组寄存器读：

| 目标 | 第一次尝试 | 第二次尝试 | 五次耗尽 |
|---|---:|---:|---:|
| PCA9557 `0x19/0x01` | `0/512` 成功 | `512/512` 成功 | 0 |
| ES7210 `0x41/0x0B` | `4/512` 成功 | 其余全部恢复 | 0 |
| QMI8658A `0x00` | `512/512` 成功 | 无需重试 | 0 |

因此旧的“PCA9557 单器件特异性”表述已过时。最新范围是：异常与**空闲后的首笔事务、访问目标及事务形态**相关；它至少覆盖 PCA9557 和 ES7210，但不覆盖 QMI8658A。降到 25 kHz 没改善，排除“100 kHz 单纯过快”作为解释。产品菜单统计写操作，本隔离表统计读操作，两组数字不可直接相加。

第二版又把“组合寄存器读是否特殊”从主要嫌疑中移除。四阶段合计结果为：

- 空闲后对 PCA9557 做纯地址探测：第一次 `0/512` 成功，第二次 `512/512` 成功；
- 空闲后对 ES7210 做纯地址探测：第一次 `0/512` 成功，第二次全部恢复；
- 空闲后对 QMI8658A 做纯地址探测：第一次 `512/512` 成功；
- 空闲后向 PCA9557 写产品同形的安全值 `0x01=0x40`：第一次 `0/512` 成功，第二次全部恢复；
- 先成功读取 QMI8658A，再立即读取 PCA9557：后者 `512/512` 第一次成功；
- 先探测不存在的地址 `0x55`，得到预期 NACK，再立即读取 PCA9557：后者 `512/512` 第一次成功。

这组证据说明：异常不要求重复起始，也不要求寄存器读；地址阶段和产品同形写操作都能复现。更关键的是，**任何前置地址事务都可能使紧随其后的 PCA9557 访问成功，甚至该前置访问本身只得到 NACK**。所以“必须先发送某条 PCA 唤醒命令”与证据不符。

第三版进一步测量了这一短时窗口。每组 64 次结果如下：

| 前置动作 | 间隔 | 随后的 PCA9557 读取 |
|---|---:|---:|
| QMI8658A 成功读取 | 0 / 0.1 / 0.25 / 0.5 / 1 / 2 / 5 ms | 均为 `64/64` 成功 |
| 不存在地址 `0x55` 的预期 NACK | 0 / 0.1 / 0.25 / 0.5 / 1 / 2 / 5 ms | 均为 `64/64` 成功 |
| 上述两类前置事务 | 10 / 20 ms | 均为 `0/64` 成功，全部地址 NACK |
| `i2c_master_bus_reset()` | 立即访问 / 再等 10 ms | 均为 `0/64` 成功，全部地址 NACK |

因此当前最窄的软件结论是：有效状态会在前置地址事务后保持至少 5 ms，但在 10 ms 前已经消失，衰减边界位于本次采样的 **5～10 ms** 之间；单纯复位 I²C FSM 并不能建立这个状态。它不支持“永久控制器状态错乱”，也不支持“PCA9557 专用唤醒命令”。更符合证据的候选是：START／地址活动后形成的短时电气或器件状态、共享支路负载的瞬态，以及主控与目标首帧容差的组合。

当前仍不能仅凭数字日志区分器件焊盘处的模拟边沿／电平、共享总线支路负载、目标器件内部首帧容差或 ESP32-C6 外设产生的首帧边沿差异。QMI 正常也不允许把问题写成整个控制器失效。诊断固件关闭了电源管理，故“自动轻睡眠唤醒导致首访失败”缺乏支持；25 kHz 与 100 kHz 结果一致，也不支持“只要降频即可解决”。

一次受控预事务或间隔短于 5 ms 的 keepalive 已被证明能绕过首访窗口，但它们仍是工程容错，不是物理根因修复。`i2c_master_bus_reset()` 已被实测否定为本问题的修复方案。若产品采用预事务，必须限制范围、统计失败并保留最终耗尽保护，不能把无界总线流量塞进所有 LCD 控制操作。

### 5.2 对几个常见疑问的直接回答

**为什么 PARLIO 曾经花屏，后续多数版本却只有背光？**

花屏只说明某个候选产生了足够的 SCLK/MOSI 活动并改变了 GRAM。后续候选同时改变过位宽、位序、命令／像素分工、GPIO Matrix 所有权和软件 CS 保护窗口；只要 D/C、CS 或第一段像素边界失配，面板就可能完全不接受后续数据。因此“曾经花屏”不能证明后续候选只差一个小参数，也不能作为 PARLIO 基本可用的验收证据。

**为什么微雪的 PARLIO 经验不能原样复用？**

微雪的 CS 直连 MCU，可由 PARLIO `valid` 与 SCLK/MOSI 处于同一硬件时基；HiYaKa 的 CS、D/C、RST 在 PCA9557 后方，只能通过另一条 I²C 控制链提前切换。二者 API 可以相似，但时序合同不等价。可复用的是 D/C 状态、位打包和实屏验收方法，不可直接复用的是“硬件同步 CS”这一板级前提。

**`PCA FIRST` 大量增长是否等于画面一定卡顿？**

不等于。第一次失败若在第 2～5 次恢复，该次 LCD 控制操作仍可能完成；立即重试带来的单次延迟通常小于人眼可辨门槛。但大量 `PCA FIRST` 表示链路没有稳定裕量：一旦五次耗尽，CASE、RASET、RAMWR、CS 或 D/C 中任一步可能终止局部刷新，用户才会看到缺字、黑块或旧像素残留。

**`PCA FIRST` 现在是否已经不存在？**

没有。恢复后的产品镜像仍持续累计首试失败；本轮隔离实验只是把现象定量为 5～10 ms 的短时窗口。当前五次即时重试让绝大多数事务恢复，失败后全屏补画让界面可以自愈，但它们都没有让底层首访 NACK 消失。

**之前的残影是否已经完全解决？**

已修正的 UI 覆盖范围和失败后全屏补画能消除当时可见残影，当前恢复镜像也多次得到完整画面；但共享 I²C 首访异常仍存在，所以不能写成根因已消失。准确表述是“当前基线能显示并具备容错恢复，M2 尚未关闭”。

## 六、从画面症状判断故障层级

### 6.1 只有背光

优先检查面板复位、`DISPON`、CS/D/C、命令窗口和数据链。背光由独立链路点亮，不能证明 ST7789 收到有效命令。PARLIO 的多版“仅背光”就是这一类。

### 6.2 规律彩条、短线或随机色块

说明面板收到了可改变 GRAM 的活动。优先检查 bit 顺序、每行字节数、CS 有效窗口、D/C、RAMWR 及分块边界。不得写成“已经渲染，只差颜色”。

### 6.3 固定边缘雪花带

优先检查屏幕方向、可视区域、RAM 偏移和初始化后的全屏清理。c0 横屏几何修正后雪花带消失，当前证据不支持把它归因 PCA9557。

### 6.4 固定文字裁切

优先检查 UI 位置、字号、行高和字符串长度。它属于布局问题，不等于传输丢包。

### 6.5 动态残影、第三行缺损或局部黑块

LVGL 以 dirty rectangle 分别刷新时间、动画和状态文字。若第三行对应的局部事务失败，其他区域仍可正常更新，而旧 GRAM 内容会保留。因此可出现“只有第三行缺字、方块仍在动”。PCA 控制链耗尽可使 CASET、RASET、RAMWR 或 CS 释放失败；一次性全屏补画能覆盖旧内容，但属于恢复措施，不是根因修复。

该因果链有日志与恢复行为支持，置信度中高；当时照片没有逐帧绑定到具体失败序号，不能把每一处残影都绝对归因 PCA。若缺损固定在同一坐标且不随刷新失败变化，应先回到布局和窗口检查。

## 七、现场调试顺序

1. **确认安全状态。** 功放隔离、温度正常、供电稳定；异常发热立即停止。
2. **确认板卡和镜像。** 记录 BASE MAC、配置名、应用 SHA、烧录偏移和写后校验。
3. **建立 GPIO Fast 基线。** 五色、横屏文字、毫秒时间和动画均应出现；记录 `PCA FIRST/EXH/DRAW FAIL`。
4. **按层隔离。** 先供电/背光，再 PCA 控制，再 GPIO6/7 数据，最后 UI；不得跨层跳结论。
5. **一次只改变一个变量。** 时钟、位序、CS 控制、D/C、窗口几何、传输后端不能同时改变。
6. **日志和画面双轨验收。** API 成功不能替代实屏；实屏完整也不能忽略 `EXH/DRAW FAIL`。
7. **实验后恢复基线。** 写后哈希、启动日志、画面和温度四项齐全才算恢复完成。

## 八、发布门禁与下一版硬件约束

GPIO Fast 进入 M2 验收前至少需要：

- 同板同镜像多次冷启动均出现完整五色和菜单；
- 持续局刷窗口内没有不可恢复的缺字、残影、黑块或死锁；
- `PCA EXH` 与 `DRAW FAIL` 达到已批准门槛，不能仅靠最后一次补画掩盖；
- TF、麦克风和其它共享资源并发时不回归；
- 故障注入后 LVGL flush 能释放，屏幕能受控恢复；
- 所有证据绑定镜像 SHA、日志和观察时间窗。

若下一版硬件仍要求 PARLIO：

- LCD CS 必须优先直连 MCU 可由 PARLIO `valid` 控制的 GPIO；
- D/C 也应优先直连 MCU，避免命令/像素跨 I²C 扩展器切换；
- 保留 SCLK、MOSI、CS、D/C、RST、VDD、PCA A0/RESET# 与 I²C 的可测点；
- 固定 PN532 模式绑带，不允许 SET0/SET1 悬空后再做共享总线归因；
- 明确 TF 与 LCD 的控制器资源合同，不能让产品路径依赖互斥诊断配置。

## 九、当前结论与置信度

| 判断 | 置信度 |
|---|---|
| GPIO Fast 能在 c0 上显示五色、横屏菜单、毫秒时间和动画 | 高 |
| 当前 PARLIO 候选没有可验收画面 | 高 |
| 花屏只证明像素活动，不证明协议基本正确 | 高 |
| PCA9557 后置 CS/D/C 缺少硬件同步是 PARLIO 的主要结构性障碍 | 中高 |
| 五次即时重试和全屏补画能显著降低用户可见故障 | 高 |
| PCA／共享 I²C 根因已经解决 | 否；高置信度未解决 |
| 动态残影主要来自失败的局部刷新未覆盖旧 GRAM | 中高 |
| 固定裁切和早期雪花带属于同一个 PCA 故障 | 否；高置信度应分层处理 |
