# 专项问题分析：HiYaKa 麦克风无有效数据

> 问题编号：`HIYAKA-AUDIO-INC-001`<br>
> 级别：`P1`<br>
> 首次确认：2026-11-04<br>
> 最新复核：2026-11-21（C1–D5 同板实测与实体链判别计划）<br>
> 影响范围：HiYaKa R1.6 原开发样机及换入样机<br>
> 当前状态：录音操作与文件写入可用，但音频数据没有到达主控；根因未确认

## 1. 结论与业务影响

- **结论：**按键、录音状态和 TF 文件流程可运行，但主控未收到有效麦克风数据。C4 有界重试后可构造音频设备；D1–D5 完成自动 WAV 对照，PCM 仍固定无效，D3 高置信确认 MCU GPIO13 端缺有效强驱动。D5 仅复现数字静音输出的 `open/write/close` 前序，不是旧整机全时序回放。11/12 同一物理样机曾读到 `0x0B=0x02`（normal），当时 GPIO13 仍无数据边沿、DMA 全 0；当前录音期 `0x0B=0x00`。故“样机永久无法进入 normal”和“进入 normal 即录音正常”都不成立，U12 输出状态与实体链仍未分离。
- **影响：**双麦录音、语音对话和所有依赖麦克风的业务不可用；TF 卡写入本身可继续测试。
- **阶段决策：**录音功能与整机发布 `NO-GO`；其它模块在功放隔离条件下 `CONDITIONAL GO`。
- **下一步：**暂停无明确判别力的软件参数排列组合。C1–C4 的受控降级与有界重试使音频设备可构造；D1–D5 仍未取得有效 PCM。D3 高置信确认 MCU GPIO13 端没有有效强驱动；D4 支持录音期 `0x0B=0x00`；D5 已执行数字静音输出的 open/write/close 前序，但结果仍阴性。软件参数排列到此停止，转向第 4.1.1 节的一次性实体链测量，重点是 U12 芯片脚供电和时钟、`U12.11 → R65 → GPIO13` 分段波形，并与同次录音状态及 PCM 对齐。旧镜像 OTA0 偏移 `0x20000`、容量 `0x3F0000`、镜像哈希与 11/12 烧录日志已核；源码提交未知但非回放门禁。暂不盲换 U12、R65 或麦克风。

“主控端没有收到有效主动数据”置信度：**高**；“U12 未输出”和“U12→GPIO13 实体链路异常”均为**中置信度**分支。

### 1.2 2026-11-20 ES7210 独立镜像实板暂态

在功放 L7 已隔离、温度正常的样机上，首轮独立诊断镜像在 ES7210 第一笔 `0x00=0xFF` 寄存器写入处失败（返回 `269`）；九笔初始化写入全部失败，未进入 DMA 采样。仅移除初始化前三次预读的对照仍相同失败，说明预读不是该失败的必要条件。后续受控镜像已能完成多寄存器控制调用并读取 DMA，但只有恒定的无效采样，麦克风仍为 `FAIL / NO-GO`。

C1 热启动绕开编解码驱动初始化，ES7210 原始首笔写仍失败。C2–E 在各自镜像/事务条件下 `0x41` 地址探测无应答，同总线 `0x6B` 有应答；关闭 I²S 时钟及降速至 25 kHz 均未恢复 C2–E 的地址应答。C25/C26 及 U12 附近 C83.2、C87/C88.2 测点均约 3.3 V；R61.2/AD0 上电 3.3 V、R62.2/AD1 上电 0 V，R60 完全断电时两端 0 Ω。这些供电、外部地址绑带和地桥测点符合设计，但不能证明 U12 焊脚或 I²C 事务健康。同板重放历史 `diagnostics/i2c-isolation` r3 后，mixed `0x41` 四阶段各 16/16 ACK、mixed `0x0B` 读事务各 128/128 返回成功，而单独 combined read 各 0/128。身份核验在 phase 0/3 mixed 末次读取 `0x3D=0x72`、`0x3E=0x10` 均成功，证明 U12 曾在特定序列下返回身份值；未初始化的纯诊断读到 `0x0B=0x00` 与数据手册默认值相容，不能据此判故障。FIRST_PROBE 同次启动首笔 `0x41` NACK、mixed 后 phase 0 为 15/16 ACK，后续三阶段各 16/16 ACK。单独移除 PCA9557 安全写后，mixed `0x41` 四阶段仍各 16/16 ACK，说明该写操作不是地址 ACK 的必要条件；但 100 kHz 的 `0x0B` 各只有 126/128 次成功，其中各 125 次读到 `0xFF`，`0x3D` 也错误读为 `0xFF`，25 kHz 的 `0x0B` 各 128/128 且全 `0x00`。因此 ACK 与 API 返回成功不能代替有效数据验证，也不能直接归因 PCA 写或认为降速已修复。新增 25 kHz 窗口对照：phase 1/2 在 mixed 中先读得身份 `0x3D=0x72`、`0x3E=0x10`，随后总线默认 100 kHz 对空地址 `0x55` probe 得到 NACK，再以 25 kHz 读两身份寄存器均返回 `ESP_ERR_INVALID_RESPONSE`；后续 mixed 访问又成功。这里同时存在速率切换、主机状态及事务时序变量，不能直接归因空地址 NACK。极简 25 kHz 首笔读对照中，首笔 ES 指针事务 NACK、round 0 三读全失败；round 1–15 每轮约 50 ms 后首个 `0x3D` 均失败，紧接的 `0x3E=0x10`、`0x0B=0x00` 均成功，末尾读 QMI `0x00=0x05` 后 ES 身份 `0x3D=0x72`、`0x3E=0x10` 成功。这证明无需历史长预热就可部分访问，但不能归因单纯上电等待不足或 QMI 特异唤醒。另一轮 25 kHz 对照在空地址 `0x55` probe 后调用 `i2c_master_bus_reset`，两次均返回 `ESP_OK`，但随后 `0x3D/0x3E` 仍返回 `ESP_ERR_INVALID_RESPONSE`；再往后的 mixed `0x0B` 各 128/128 成功。显式 bus reset 未立即恢复读取，不能把问题直接归为单纯 IDF 状态机残留。交换极简程序每轮三寄存器顺序后，round 1–15 约 50 ms 空闲后的首笔改为 `0x0B` 并 15/15 NACK，随后 `0x3E=0x10`、`0x3D=0x72` 均 15/15 成功；失败跟随首笔，而非 `0x3D` 特异。安全写入实验在 POST_QMI 身份 `0x72/0x10` 后，两轮身份及 `0x12` 原值门禁均 NACK，程序明确跳过测试写入，因此没有写入结果。25 kHz 只读突发中 `0x3D` 曾在 API 成功时误读为 `0x77`，`0x12` 首读 NACK、次读 `0x00`；10 kHz 只读突发中 `0x3D` 三读全 NACK、`0x3E` 三读均为 `0x10`，`0x12` 同样首读 NACK、次读 `0x00`。降到 10 kHz 也未稳定读取。旧版 I²C 驱动的 25 kHz 只读对照两次复位均复现约 50 ms 空闲后首笔失败，burst 第二次 `0x3D` 虽返回 `ESP_OK` 却误读为 `0xFF`，`0x12` 首读失败、次读 `0x00`；旧驱动同样异常，不能归因新版 I²C API 独有。该对照未写入芯片配置，也未采集 PCM。GPIO 开漏软件 I²C 因果作用。后续 GPIO 软件 I²C 对 `0x12` 的单次写回实验中，前置读门禁通过，但首次 toggle 写仍在地址阶段 NACK，恢复 `0x00` 成功，`pass=0`；有界重试版的两次复位均在 toggle 首笔 NACK、第二笔 ACK 后读回 `0x20`，restore 首笔寄存器地址 NACK、第二笔 ACK 后读回 `0x00`，最终身份 `0x72/0x10`，单寄存器 ### 1.3 样机身份与历史状态

早期日志对应样机标识 `…:d6:b4`，其 `0x0B=0x02` 且 DMA 全 0；它与本轮样机 `…:d6:c0` **不是同一物理板**，不能作为同板 A/B。更关键的是，11/12 的 `…:d6:c0` 日志与本轮 esptool BASE MAC 对上：ACT_B 开始录音后，该板曾读到 `0x0B=0x02`，但原始 RX 1024 B 全 0、GPIO13 无上升沿；本轮同板诊断读到 `0x0B=0x00`、DMA 全 `-1`。11/12 与本轮固件和部分寄存器值不同（例如 `0x43/0x44` 分别为 `0x18`、`0x10`），因此当前不能把状态差异直接归因永久硬件损坏，也不能据历史 normal 宣称麦克风曾正常。11/12 日志约 4.32 秒启用输出、21.301 秒记录输出 enable 关闭、88.041 秒才由 ACT_B 触发录音，不能据此声称此前时钟连续驻留约 84 秒；本轮 enable 后 90 秒轮询不复刻那段时序。完整样机标识仅保留在本地原始日志；本摘要使用遮蔽后两字节，证据文件与 SHA-256 见附件。

## 2. 现象

两块样机都能通过 ACT_B 启停录音、切换红灯并在 TF 卡创建和关闭 WAV 文件，但 WAV 峰值为 0，无法回放出有效声音。多种采样和增益设置下，原始样本固定为全 0 或全 `-1`；改变 GPIO13 内部弱上拉/下拉后，固定码值随之改变，GPIO13 没有观察到音频数据边沿。

主控内部 I²S 回环能够接收已知数据，主控端 MCLK/BCLK/WS 有时钟。ES7210 地址 `0x41` 可访问，但状态寄存器 `0x0B` 在不同实验中出现 0 和 2；尚未测量时钟是否真正到达 U12 引脚，也未比较 U12.11、R65 两侧和 GPIO13 的同步波形。

2026-11-12 当前样机的同板对照新增一项前置阻断：无屏幕镜像及专用仅输入镜像均出现控制事务 NACK。专用镜像的主控 I²S 内部回环通过，但 ES7210 初始化寄存器写入失败，未进入有效 PCM 采集；跳过启动 I²C 扫描后故障仍复现。此次不能用“无 PCM”推断 U12.11 或 R65 的实体故障，也不能单凭 NACK 判定 PCB 总线电气不良。

## 3. 排查分析

### 3.1 因果链

```text
ES7210 未产生 SDOUT，或 SDOUT 到 GPIO13 的实体链路中断
→ GPIO13 只呈现内部弱拉决定的固定电平
→ I²S DMA 得到全 0 / 全 -1
→ WAV 文件能创建但没有有效声音
```

### 3.2 已确认事实

- ACT_B、录音状态灯、TF 文件创建和关闭正常，按键映射及文件系统不是当前直接原因。
- MCU 内部 I²S 回环重复通过，排除主控 I²S 接收/DMA 完全失效。
- MCU 端 MCLK/BCLK/WS 可见，而 GPIO13 无数据边沿；弱上拉/下拉能改变固定码值，说明 MCU 采样端没有获得足够强的外部主动驱动。
- 冻结原理图和 PCB 显示 U12.11/SDOUT1 经 R65（51 Ω）到 ESP32-C6 GPIO13；静态网表正确不等于实板端到端连通或 U12 已输出。
- I²C 应答和寄存器可读，只能证明控制接口可访问，不能证明 U12 全部电源、时钟及 SDOUT 工作。
- 当前样机即使不运行屏幕和启动全地址扫描，PCA9557 及 ES7210 的控制写入也曾失败；PN532 SET0/SET1 此时悬空。R8/A0 对地电压曾在 0 与 3.3 V 间变化，但本轮恢复横屏固件后复测为稳定 3.3 V，不能继续把地址脚漂移当作当前已证实根因。共享 I²C 条件尚未稳定，不能把 ES7210 控制失败定为单一芯片故障。
- 独立最小 I²C 程序不运行 LCD、音频及启动扫描；`0x19/0x41/0x18` 地址探测均 16/16 应答，PCA9557 安全写 128/128 成功，但单独重复起始读 PCA9557 和 ES7210 大量 NACK，ES7210 在交替事务中 128/128 读成功。故当前错误还明显依赖事务形状与访问顺序；不能把所有旧日志中的“写入失败”一概解释为芯片或走线损坏。详见[同板对照证据](2026-11-12-pca-audio-shared-i2c-ab-evidence.md)。

### 3.4 2026-11-20 固件与版本交叉复核

- 在线 `YaKa v2.0`（project UUID `61d2076a056e4cb4b9c5b734f0f793e9`）与 `YaKa v3.0`（project UUID `8f58125ad0d64436afbfeeeb03d3b159`）的 ES7210 原理图拓扑高度相似：均为双 ZTS6216 模拟麦克风、MICBIAS12 供电、SDOUT1 经 51 Ω 串联电阻到 MCU，SDOUT2/TDMIN 的 0 Ω电阻不贴。暂未找到只存在于 v3.0 的明显原理图断链。
- 旧 v2.x 固件同样使用“标准 I²S 输出 + 4-slot TDM 输入”的共享时钟架构；这是继承风险，不是 v3.0 新增差异。`esp_codec_dev 1.6.2` 会在 `open()` 时经数据接口重设格式并启用通道，因此不能仅凭构造期配置或 `bclk_div=8` 将其定为已证实根因。
- 历史的 512 kHz BCLK 来自 16 kHz、2-slot、16-bit 标准 I²S 诊断，数值正确；不能用它推断生产 4-slot TDM 的实际帧长。生产 TDM 仍需用逻辑分析仪实测 LRCK/BCLK/逐槽数据后关闭。
- 生产配置选中 `MIC1 | MIC2 | MIC3`，但上层 `input_channels_` 在开启参考通道时仍为 2。结合 ES7210 TDM 顺序 `MIC1, MIC3, MIC2, MIC4`，当前有中高风险只将“MIC1 + MIC3 播放参考”交给上层，而 MIC2 未进入算法链。这不解释 GPIO13 无边沿，但即使 PCM 恢复，也必须再验证产品需求是 `MR` 还是双麦加参考的 `MMR`。
- ESP32-C6 GPIO12/13 复位默认可用于 USB-JTAG，但 ESP-IDF 文档明确普通 GPIO 重配会关闭该 USB-JTAG 功能。它是需要显式固定的 pin-mux/启动约束，不是当前已证实根因。

### 3.5 2026-11-12 同板对照：控制通信的历史阶段

无屏幕基线、旧镜像及专用仅输入镜像均未能在当前样机完成音频初始化。专用镜像的主控 I²S 内部回环通过，但 ES7210 首批寄存器写入失败；跳过启动 I²C 扫描后，PCA9557 仍有写入与读回失败，ES7210 仍无法打开。由此确认：屏幕刷新和启动扫描都不是本次控制事务失败的必要条件；本次没有有效 PCM 结果，不能用来判断 U12.11 或 R65 是否故障。

当时 PN532 的 SET0/SET1 电阻均已拆除、模式脚悬空；R8/A0 早先有跳变读数，该轮复测 A0 侧稳定 3.3 V。最小程序发现地址探测稳定而寄存器事务有条件地失败；这段只记录 11/12 的诊断阶段。后续已完成 C1–D5 软件对照，当前下一步改为第 4.1.1 节的实体链测量。模式绑带、焊接、总线波形及事务时序的具体根因仍未知。镜像、日志和哈希见[同板对照证据](2026-11-12-pca-audio-shared-i2c-ab-evidence.md)。

## 4. 解决方法

### 4.1 当前 PCBA 止损与判别

继续保持功放 L7 断开、GPIO23/PA_EN 关闭和扬声器空置，避免功放故障干扰诊断。当前阶段不要求 PN532 返修。以下为此前制定的分层 Gate，控制面已有 C1–D5 实板结果；当前优先执行第 4.1.1 节的一次性实体测量，前一级未证实时不对后一级下根因结论：

1. **控制平面：**独立 ES7210 输入程序不初始化 LCD、PN532、PCA9557 和 ES8311；I²C 100 kHz；记录每笔初始化写入，并读回 `0x00/01/02/06/08/0B/11/12/40–4C`。要求连续三次冷启动初始化完成且 `0x0B=2`。
2. **芯片脚供电与时钟：**在同一录音窗口测 U12.6/VDDP、U12.7/VDDD、U12.22/VDDA、U12.23/VDDM、U12.5/MCLK、U12.9/BCLK、U12.10/LRCK；不用 MCU 端波形代替 U12 焊盘波形。
3. **SDOUT 分段：**依次测 `U12.11 → R65 U12 侧 → R65 MCU 侧 → GPIO13`。U12.11 有波形而 R65 后无，定位焊盘/R65/过孔/走线；R65 后有波形而 DMA 固定，再查 GPIO matrix/pin mux/I²S 接收配置；U12.11 无波形且供电、时钟、状态正确，再查输出配置、芯片或装配。
4. **模拟前端：**数字输出恢复后再测 MICBIAS12、两颗麦克风 VDD、MIC1/MIC2 输入端与单麦分别启用。安静环境或单颗麦克风故障通常不足以解释 SDOUT 随 GPIO 弱拉变为全 0/全 1。
5. **产品通道契约：**先验证双槽标准 I²S 下 MIC1/MIC2，再验证四槽 TDM 逐槽数据、`MIC1 + MIC2 + MIC3` 真实内存顺序与上层 AFE 的 `MR/MMR` 契约。

保留 A/B 固件作为后续诊断工具，但主报告只以原始 PCM、SDOUT 分段波形和 TF WAV 作为结果，不以“读取 API 成功”判断录音成功。

当前不建议盲目更换 U12 或 R65。“默认无虚焊”可以用于安排软件和芯片脚测量先后，但在 U12.11/R65/GPIO13 分段波形之前，不能升级为已证实事实。

#### 4.1.1 一次性实体链测量清单（待执行）

以下测点来自已冻结的 HiYaKa 原理图/接口表及本专项交叉审计；不依赖实时 EDA。按顺序在**同一块板、同一录音镜像和同一次有效录音窗口**记录样机标识、镜像 SHA、MASTER/USB/电池状态、测量时间和原始波形。若焊盘太密，停在可安全接触的电容或电阻焊盘，不用表笔强触 U12/FPC 相邻脚。功放保持隔离、PA_EN 低；出现异常升温或异味立即断电。

| 顺序 | 精确目标与方法 | 工具及判别分支 |
| --- | --- | --- |
| 1. 电源 | 黑表笔固定 GND；在录音前和录音中分别量 `AU_3V3` 的 C25/C26 非地端，以及 U12 近旁 C83.2、C87/C88.2。冻结原理图的 U12.6/VDDP、U12.7/VDDD、U12.22/VDDA、U12.23/VDDM 为进一步的芯片脚目标；仅在探头可安全落点时测。 | **万用表可做直流电压**。此前 C25/C26、C83.2、C87/C88.2 已约 3.3 V，但须与本次录音同窗复核；若近端掉电，先查供电/焊接。电容 3.3 V 仍不能证明全部 U12 脚接触、纹波或上电瞬态。纹波和掉压时序须用示波器。 |
| 2. 时钟 | 录音窗口同时看 U12.5/MCLK、U12.9/BCLK、U12.10/LRCK（WS）；MCU 端参考为 GPIO0/3/12。 | **逻辑分析仪或示波器**。主控此前测到约 4.096 MHz/512 kHz/16 kHz，U12 焊盘尚未测。若 MCU 有而 U12 脚无，查中间网络/焊点；若 U12 三钟均有，再进入 SDOUT。万用表直流均值不能证明时钟存在或频率正确。 |
| 3. 芯片数据脚 | 在同一录音窗口测 U12.11/SDOUT1，同时保存 ES7210 `0x0B` 读值与原始 PCM。 | **逻辑分析仪或示波器**。若 U12.11 有数据边沿而 MCU GPIO13 无，实体传输链优先；若 U12.11 无边沿，即使供电和时钟正常，也须进一步查 `0x0B` 状态、输出使能、焊接及芯片，不能直接判 U12 损坏。万用表不能判定数字数据。 |
| 4. 串阻分段 | 依次量 R65 靠 U12 一端、R65 靠 MCU 一端的同步 SDOUT 波形；断电后可复核 R65 跨件约 51 Ω，并查两侧到 U12.11/GPIO13 的连续性。 | **上电波形用逻辑分析仪或示波器；断电电阻/通断用万用表**。U12 侧有、R65 后无，查 R65/焊盘；R65 两侧有而 GPIO13 无，查过孔/走线/MCU 焊点。已测 51 Ω 只证明电阻本体，不证明板上全链连续。通断测试前 MASTER OFF、拔 USB、断电池并确认储能电容放电。 |
| 5. MCU 输入 | 同步测 GPIO13 引脚/可达测试点与固件 DMA。 | **逻辑分析仪或示波器**。GPIO13 有正确边沿而 PCM 仍固定，回查 GPIO matrix、I²S RX 路由、格式/槽位；GPIO13 仍无边沿且 U12.11 有边沿，则回到分段走线。只有万用表时可完成步骤 1 的直流与步骤 4 的断电通断，不能用电压均值替代步骤 2–5 的波形证据。 |

测量后只按第一个分叉点做返修或固件修改，并在相同条件下重测状态、分段波形与有变化的双声道 PCM；在此之前不把 U12、R65 或软件时序定为根因。

### 4.2 下一版永久修复

只把实测确认的根因转成原理图、PCB、BOM、SMT 工艺或驱动 ECO；完成双麦、播放参考、连续录音和并发测试后再纳入量产基线。

### 4.3 禁止采用的做法

- 不用 WAV 文件存在或样本“非零”代替有效音频判定；
- 不用万用表直流均值代替 I²S 数字波形；
- 在没有分段波形证据前，不把“换 U12”“恢复 L7”或“修改 PCM 后处理”定为修复方案。

## 5. 验证与关闭标准

- [ ] 固定根因、返修位置或代码差异，并用同条件 A/B 重复证明；
- [ ] 多次冷启动后 U12 状态、电源、时钟及 U12.11→GPIO13 数据链一致；
- [ ] MIC1/MIC2 原始 PCM 分别随声源变化，静音时有合理底噪，不再固定全 0/全 `-1`；
- [ ] 逐槽证明 MIC1、MIC2 和 MIC3 播放参考的真实排列，并证明上层 AFE 的 `MR/MMR` 配置符合产品要求；
- [ ] ACT_B 录音 WAV 可回放、两路对应正确，连续录音、关闭和重启后仍正常；
- [ ] 不引入 U11 发热或其它 I²C/外设回归，并保存波形、日志、样机编号和固件 SHA。
