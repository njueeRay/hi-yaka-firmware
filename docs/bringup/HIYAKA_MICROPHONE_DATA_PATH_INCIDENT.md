# 专项问题分析：HiYaKa 麦克风无有效数据

> 问题编号：`HIYAKA-AUDIO-INC-001`<br>
> 级别：`P1`<br>
> 首次确认：2026-11-04<br>
> 最新复核：2026-11-20（YaKa v2.x/v3.0 原理图、固件与 `esp_codec_dev 1.6.2` 交叉核对）<br>
> 影响范围：HiYaKa R1.6 原开发样机及换入样机<br>
> 当前状态：录音操作与文件写入可用，但音频数据没有到达主控；根因未确认

## 1. 结论与业务影响

- **结论：**按键、录音状态和 TF 文件流程曾正常，但主控未收到有效麦克风数据。本轮隔离镜像经有限重试已完成官方多寄存器控制调用和读回；AH 进一步走通 input-only 音频设备 wrapper 路径及九项寄存器语义核对，但 `0x0B` 仍为 power-down、DMA 固定 `-1`，未通过 PCM 门禁。11/12 同一物理样机曾读到 `0x0B=0x02`（normal），当时 GPIO13 仍无数据边沿、DMA 全 0；故“该样机永久无法进入 normal”和“进入 normal 即录音正常”都不成立。AH 未复刻旧整机先播放后录音时序，驱动读写语义、器件状态与物理链路仍未最终分离。
- **影响：**双麦录音、语音对话和所有依赖麦克风的业务不可用；TF 卡写入本身可继续测试。
- **阶段决策：**录音功能与整机发布 `NO-GO`；其它模块在功放隔离条件下 `CONDITIONAL GO`。
- **下一步：**暂停无明确判别力的软件参数排列组合。优先在用户在场时以已定位的旧镜像复现同板“先播放、后 ACT_B 录音”路径，或在同一录音窗口测 U12 芯片脚供电、MCLK/BCLK/WS 与 `U12.11 → R65 → GPIO13` 分段波形。旧镜像 OTA0 偏移 `0x20000`、容量 `0x3F0000`、镜像哈希与 11/12 烧录日志已核；源码提交尚未知，但不是原镜像回放的前置门禁。暂不盲换 U12、R65 或麦克风。

“主控端没有收到有效主动数据”置信度：**高**；“U12 未输出”和“U12→GPIO13 实体链路异常”均为**中置信度**分支。

### 1.2 2026-11-20 ES7210 独立镜像实板暂态

在功放 L7 已隔离、温度正常的样机上，首轮独立诊断镜像在 ES7210 第一笔 `0x00=0xFF` 寄存器写入处失败（返回 `269`）；九笔初始化写入全部失败，未进入 DMA 采样。仅移除初始化前三次预读的对照仍相同失败，说明预读不是该失败的必要条件。后续受控镜像已能完成多寄存器控制调用并读取 DMA，但只有恒定的无效采样，麦克风仍为 `FAIL / NO-GO`。

C1 热启动绕开编解码驱动初始化，ES7210 原始首笔写仍失败。C2–E 在各自镜像/事务条件下 `0x41` 地址探测无应答，同总线 `0x6B` 有应答；关闭 I²S 时钟及降速至 25 kHz 均未恢复 C2–E 的地址应答。C25/C26 及 U12 附近 C83.2、C87/C88.2 测点均约 3.3 V；R61.2/AD0 上电 3.3 V、R62.2/AD1 上电 0 V，R60 完全断电时两端 0 Ω。这些供电、外部地址绑带和地桥测点符合设计，但不能证明 U12 焊脚或 I²C 事务健康。同板重放历史 `diagnostics/i2c-isolation` r3 后，mixed `0x41` 四阶段各 16/16 ACK、mixed `0x0B` 读事务各 128/128 返回成功，而单独 combined read 各 0/128。身份核验在 phase 0/3 mixed 末次读取 `0x3D=0x72`、`0x3E=0x10` 均成功，证明 U12 曾在特定序列下返回身份值；未初始化的纯诊断读到 `0x0B=0x00` 与数据手册默认值相容，不能据此判故障。FIRST_PROBE 同次启动首笔 `0x41` NACK、mixed 后 phase 0 为 15/16 ACK，后续三阶段各 16/16 ACK。单独移除 PCA9557 安全写后，mixed `0x41` 四阶段仍各 16/16 ACK，说明该写操作不是地址 ACK 的必要条件；但 100 kHz 的 `0x0B` 各只有 126/128 次成功，其中各 125 次读到 `0xFF`，`0x3D` 也错误读为 `0xFF`，25 kHz 的 `0x0B` 各 128/128 且全 `0x00`。因此 ACK 与 API 返回成功不能代替有效数据验证，也不能直接归因 PCA 写或认为降速已修复。新增 25 kHz 窗口对照：phase 1/2 在 mixed 中先读得身份 `0x3D=0x72`、`0x3E=0x10`，随后总线默认 100 kHz 对空地址 `0x55` probe 得到 NACK，再以 25 kHz 读两身份寄存器均返回 `ESP_ERR_INVALID_RESPONSE`；后续 mixed 访问又成功。这里同时存在速率切换、主机状态及事务时序变量，不能直接归因空地址 NACK。极简 25 kHz 首笔读对照中，首笔 ES 指针事务 NACK、round 0 三读全失败；round 1–15 每轮约 50 ms 后首个 `0x3D` 均失败，紧接的 `0x3E=0x10`、`0x0B=0x00` 均成功，末尾读 QMI `0x00=0x05` 后 ES 身份 `0x3D=0x72`、`0x3E=0x10` 成功。这证明无需历史长预热就可部分访问，但不能归因单纯上电等待不足或 QMI 特异唤醒。另一轮 25 kHz 对照在空地址 `0x55` probe 后调用 `i2c_master_bus_reset`，两次均返回 `ESP_OK`，但随后 `0x3D/0x3E` 仍返回 `ESP_ERR_INVALID_RESPONSE`；再往后的 mixed `0x0B` 各 128/128 成功。显式 bus reset 未立即恢复读取，不能把问题直接归为单纯 IDF 状态机残留。交换极简程序每轮三寄存器顺序后，round 1–15 约 50 ms 空闲后的首笔改为 `0x0B` 并 15/15 NACK，随后 `0x3E=0x10`、`0x3D=0x72` 均 15/15 成功；失败跟随首笔，而非 `0x3D` 特异。安全写入实验在 POST_QMI 身份 `0x72/0x10` 后，两轮身份及 `0x12` 原值门禁均 NACK，程序明确跳过测试写入，因此没有写入结果。25 kHz 只读突发中 `0x3D` 曾在 API 成功时误读为 `0x77`，`0x12` 首读 NACK、次读 `0x00`；10 kHz 只读突发中 `0x3D` 三读全 NACK、`0x3E` 三读均为 `0x10`，`0x12` 同样首读 NACK、次读 `0x00`。降到 10 kHz 也未稳定读取。旧版 I²C 驱动的 25 kHz 只读对照两次复位均复现约 50 ms 空闲后首笔失败，burst 第二次 `0x3D` 虽返回 `ESP_OK` 却误读为 `0xFF`，`0x12` 首读失败、次读 `0x00`；旧驱动同样异常，不能归因新版 I²C API 独有。该对照未写入芯片配置，也未采集 PCM。GPIO 开漏软件 I²C 避开硬件控制器后，约 50 ms 空闲后的首笔仍有地址写 NACK，后续身份值在该轮可读，说明硬件 I²C 控制器不是此类失败的唯一必要条件。增加 I²S 静音写入的 MCLK 候选两次复位各记录 58 次软件写成功，但首笔及突发读仍有 NACK；没有物理 MCLK 波形，且该镜像的静音发送失败分支缺退避，审计为 NO-GO，已烧回无 I²S 软件 I²C 只读镜像。不能据此判断 MCLK 因果作用。后续 GPIO 软件 I²C 对 `0x12` 的单次写回实验中，前置读门禁通过，但首次 toggle 写仍在地址阶段 NACK，恢复 `0x00` 成功，`pass=0`；有界重试版的两次复位均在 toggle 首笔 NACK、第二笔 ACK 后读回 `0x20`，restore 首笔寄存器地址 NACK、第二笔 ACK 后读回 `0x00`，最终身份 `0x72/0x10`，单寄存器 `pass=1`。由此排除“控制面完全不可写”的绝对假说，但没有证明持续稳定、完整 ES7210 初始化或 PCM 采样。芯片状态、主机行为和电气/时序条件仍未区分，麦克风仍为 `FAIL / NO-GO`。随后基于官方 `esp_codec_dev 1.6.2`（读改写预读失败即返回的临时补丁）的完整控制序列隔离两次复位均完成构造、16 kHz/16 bit 双通道配置和 enable 调用；各有 59 次成功控制写、69/70 次底层尝试、0 次终态失败，关键寄存器读回与最后写值一致。诊断镜像把 `0x43/0x44` 预期写成 `0x1A`，但官方 enable 路径再次选择麦克风，最终实际写入和读回 `0x10`，因此这两项 semantic=0 是诊断预期错误。真正未通过的是 `0x0B`：两次均读到 `0x00`、normal=0，按手册为 power-down；本镜像未启动 I²S/MCLK 或采样 PCM，不能据此定位芯片、时钟或电气根因。麦克风仍为 `FAIL / NO-GO`。再启用 I²S RX 的两次复位中，MCU GPIO3/12 软件读到 BCLK 约 74235 个边沿、WS 2322 个边沿；U12 芯片时钟脚未测。DMA 首个 1024 B/512 词虽返回 `ESP_OK`，左右各 256 词却全为 `-1`、零变化，日志 `nonzero=512` 仅是 `-1≠0`，不能算有效音频。`0x0B` 在 DMA 前后仍为 `0x00`，三窗 PCM 候选因状态门禁失败未运行。同镜像 PCNT 两次复位在 MCU GPIO12/WS、GPIO3/BCLK、GPIO0/MCLK 读得约 16.37 kHz、512 kHz、4.096 MHz；`0x0B=0x00` 与 DMA 全 `-1` 未改变。PCNT 只测 MCU GPIO 输入路径，不能替代 U12.5/9/10 焊盘测量。加 TX 静音馈送的两次复位各有 71 次完整写与 58 次失败写，MCU 三钟仍约 16 kHz/512 kHz/4.096 MHz，`0x0B` 与 DMA 全 `-1` 不变；这不是连续全成功的 TX 试验。再将同一 TX+RX 诊断的采样率从 16 改为 24 kHz，两次复位 MCU 三钟相应升至约 23.81 kHz/767.73 kHz/6.14 MHz，控制面瞬态与终态失败均为 0；但 `0x0B` 前后仍 `0x00`、DMA 左右词仍全 `-1`，PCM 三窗未执行，且 TX 每次仍有 57 次失败写。该单因素对照在已测条件下结果为阴性，不证明 U12 芯片脚实测时钟或采样率在所有配置下无影响。保持 24 kHz 再将有效样本 16 bit 的时隙从 16 加宽至 32 bit，两次复位的 MCU BCLK 约翻倍至 1.534 MHz、WS/MCLK 仍约 23.83 kHz/6.144 MHz；但 `0x0B` 前后仍 `0x00`，DMA 全 `-1`，TX 每次仍有 56 次失败写。这说明单靠此时隙宽度变化未使本测试进入正常态，不能代替 U12 时钟脚实测。进一步保持 TX 标准双槽 32 bit、改 RX 为四槽 16 bit TDM（同为 64 bit 帧），两次复位的 MCU 三钟约 23.8 kHz/1.536 MHz/6.144 MHz，但 `0x0B` 前后仍 `0x00`、TDM DMA 2048 B 全 `-1`；TX 每次仍有 57 次失败写。这一配置对照仍为阴性，不能推定 U12 物理输入时钟或 TDM 数据槽。回到 16 kHz 标准双槽、MIC1+2 并在 enable 后仅持续等待/读状态：至 90 秒的 18 次 wrapper A/B。后续的 I²C 只读交叉已在同一镜像两次复位完成：GPIO 软件 I²C 25 kHz 和硬件 I²C 25 kHz split 均读得 ES7210 身份 `0x72/0x10`、状态 `0x0B=0x00`；软件快照 `0x14/0x15=0x00`、`0x47–0x4A=0x08`、`0x4B=0x00`、`0x4C=0xFF`，与既有同板快照对应值一致。硬件 I²C 内部上拉的源码单因素对照两次复位中，100 kHz combined 各六笔均返回 `ESP_ERR_INVALID_RESPONSE`，25 kHz split 各六笔事务成功并读出身份 `0x72/0x10`、状态 `0x00`；主 codec 状态及 DMA 全 `-1` 未变。与内部上拉开启时 100 kHz 合计 1/12 成功相比，样本不足以判断关闭更差或开启能修复，只能确认关闭未恢复本轮 100 kHz 稳定读，25 kHz 状态结论未变。进一步的 input-only 音频设备 wrapper 路径包两次复位均完成 `open/data_fmt/data_enable` 和增益调用、9 项控制寄存器语义读回，`0x43/0x44=0x18`、控制终态错误 0；但 `0x0B` 在 DMA 前后仍为 `0x00`、1024 B DMA 左右词全 `-1`。MCU GPIO PCNT 显示 WS/BCLK/MCLK 约 15.86 kHz/512 kHz/4.094 MHz，U12 焊盘未测。该路径包不是单因素，未复刻旧整机先播放后 ACT_B 录音的时序；只能确认此输入路径包未恢复麦克风。后续优先复现已定位旧镜像的真实 ACT_B 路径或测 U12 近端，暂不继续无目标的软件排列组合。历史 Yaka 工程锁定 `esp_codec_dev 1.3.5`，其未打补丁 `es7210.c` 与当前 1.6.2 原始文件 SHA-256 完全一致，不能归因两版 ES7210 驱动源码算法回归。下一步须区分 MCU 时钟输出与 U12 实际输入，证明芯片进入正常态后再验证多窗 PCM 和数据链路。日志及镜像哈希见独立证据附件 `2026-11-20-es7210-control-ab-evidence.md`。

### 1.3 样机身份与历史状态

早期日志对应样机标识 `…:d6:b4`，其 `0x0B=0x02` 且 DMA 全 0；它与本轮样机 `…:d6:c0` **不是同一物理板**，不能作为同板 A/B。更关键的是，11/12 的 `…:d6:c0` 日志与本轮 esptool BASE MAC 对上：ACT_B 开始录音后，该板曾读到 `0x0B=0x02`，但原始 RX 1024 B 全 0、GPIO13 无上升沿；本轮同板诊断读到 `0x0B=0x00`、DMA 全 `-1`。11/12 与本轮固件和部分寄存器值不同（例如 `0x43/0x44` 分别为 `0x18`、`0x10`），因此当前不能把状态差异直接归因永久硬件损坏，也不能据历史 normal 宣称麦克风曾正常。11/12 日志约 4.32 秒启用输出、21.301 秒记录输出 enable 关闭、88.041 秒才由 ACT_B 触发录音，不能据此声称此前时钟连续驻留约 84 秒；本轮 enable 后 90 秒轮询不复刻那段时序。完整样机标识仅保留在本地原始日志；本摘要使用遮蔽后两字节，证据文件与 SHA-256 见附件。
## 2. 现象

两块样机都能通过 ACT_B 启停录音、切换红灯并在 TF 卡创建和关闭 WAV 文件，但 WAV 峰值为 0，无法回放出有效声音。多种采样和增益设置下，原始样本固定为全 0 或全 `-1`；改变 GPIO13 内部弱上拉/下拉后，固定码值随之改变，GPIO13 没有观察到音频数据边沿。

主控内部 I²S 回环能够接收已知数据，主控端 MCLK/BCLK/WS 有时钟。ES7210 地址 `0x41` 可访问，但状态寄存器 `0x0B` 在不同实验中出现 0 和 2；尚未测量时钟是否真正到达 U12 引脚，也未比较 U12.11、R65 两侧和 GPIO13 的同步波形。

2026-11-12 当前样机的同板对照新增一项前置阻断：无屏幕镜像及专用仅输入镜像均出现控制事务 NACK。专用镜像的主控 I²S 内部回环通过，但 ES7210 初始化寄存器写入失败，未进入有效 PCM 采集；跳过启动 I²C 扫描后故障仍复现。此次不能用“无 PCM”推断 U12.11 或 R65 的实体故障，也不能单凭 NACK 判定 PCB 总线电气不良。

## 3. 排查分析

### 3.1 因果链

```text
ES7210 未产生 SDOUT，或 SDOUT 到 GPIO13 的实体链路中断
→ GPIO13 只呈现内部弱拉决定的固定电平
→ I²S DMA 得到全 0 / 全 -1
→ WAV 文件能创建但没有有效声音
```

### 3.2 已确认事实

- ACT_B、录音状态灯、TF 文件创建和关闭正常，按键映射及文件系统不是当前直接原因。
- MCU 内部 I²S 回环重复通过，排除主控 I²S 接收/DMA 完全失效。
- MCU 端 MCLK/BCLK/WS 可见，而 GPIO13 无数据边沿；弱上拉/下拉能改变固定码值，说明 MCU 采样端没有获得足够强的外部主动驱动。
- 冻结原理图和 PCB 显示 U12.11/SDOUT1 经 R65（51 Ω）到 ESP32-C6 GPIO13；静态网表正确不等于实板端到端连通或 U12 已输出。
- I²C 应答和寄存器可读，只能证明控制接口可访问，不能证明 U12 全部电源、时钟及 SDOUT 工作。
- 当前样机即使不运行屏幕和启动全地址扫描，PCA9557 及 ES7210 的控制写入也曾失败；PN532 SET0/SET1 此时悬空。R8/A0 对地电压曾在 0 与 3.3 V 间变化，但本轮恢复横屏固件后复测为稳定 3.3 V，不能继续把地址脚漂移当作当前已证实根因。共享 I²C 条件尚未稳定，不能把 ES7210 控制失败定为单一芯片故障。
- 独立最小 I²C 程序不运行 LCD、音频及启动扫描；`0x19/0x41/0x18` 地址探测均 16/16 应答，PCA9557 安全写 128/128 成功，但单独重复起始读 PCA9557 和 ES7210 大量 NACK，ES7210 在交替事务中 128/128 读成功。故当前错误还明显依赖事务形状与访问顺序；不能把所有旧日志中的“写入失败”一概解释为芯片或走线损坏。详见[同板对照证据](2026-11-12-pca-audio-shared-i2c-ab-evidence.md)。

### 3.3 已排除、削弱与待验证分支

| 分支 | 当前判断与证据 | 置信度 | 最短判别方法 |
|---|---|---|---|
| ES7210 控制事务/初始化顺序阻断 | 同板无屏幕、跳过扫描仍失败；最小程序地址应答和 PCA 安全写稳定，寄存器读显著依赖事务顺序；PN532 模式脚悬空，R8/A0 本轮稳定 3.3 V | 高：存在前置阻断；驱动语义、器件状态与物理层均未分离 | 先比较驱动事务序列和初始化顺序，取得连续有效读写；模式绑带留作最终硬件归因条件。 |
| U12 未满足有效输出条件 | `0x0B` 状态不一致，尚未量芯片脚电源/时钟和 U12.11 | 中 | 同一录音窗口测 U12 电源、时钟、状态和 U12.11 波形。 |
| U12.11 到 GPIO13 焊接、R65、过孔或走线异常 | 网表正确，但无端到端同步波形；GPIO13 只受弱拉影响 | 中 | 同时比较 U12.11、R65 两侧和 GPIO13，并做断电连通。 |
| MCU I²S/DMA 完全失效 | 内部回环通过，MCU 时钟存在 | 低 | 仅当 GPIO13 已有正确波形但 DMA 仍固定时再查 GPIO matrix。 |
| WAV 封装、增益或按键问题 | 原始 DMA 已固定，文件流程正常，增益变化无效 | 低 | 不再作为首要分支。 |
| 功放 L7 拆除导致麦克风失效 | L7 位于扬声器功放输出链，不在 ES7210 采集路径 | 低；仅保留返修误伤可能 | 检查返修区域是否机械损伤相邻网络，无需恢复 L7 验证录音。 |

### 3.4 2026-11-20 固件与版本交叉复核

- 在线 `YaKa v2.0`（project UUID `61d2076a056e4cb4b9c5b734f0f793e9`）与 `YaKa v3.0`（project UUID `8f58125ad0d64436afbfeeeb03d3b159`）的 ES7210 原理图拓扑高度相似：均为双 ZTS6216 模拟麦克风、MICBIAS12 供电、SDOUT1 经 51 Ω 串联电阻到 MCU，SDOUT2/TDMIN 的 0 Ω电阻不贴。暂未找到只存在于 v3.0 的明显原理图断链。
- 旧 v2.x 固件同样使用“标准 I²S 输出 + 4-slot TDM 输入”的共享时钟架构；这是继承风险，不是 v3.0 新增差异。`esp_codec_dev 1.6.2` 会在 `open()` 时经数据接口重设格式并启用通道，因此不能仅凭构造期配置或 `bclk_div=8` 将其定为已证实根因。
- 历史的 512 kHz BCLK 来自 16 kHz、2-slot、16-bit 标准 I²S 诊断，数值正确；不能用它推断生产 4-slot TDM 的实际帧长。生产 TDM 仍需用逻辑分析仪实测 LRCK/BCLK/逐槽数据后关闭。
- 生产配置选中 `MIC1 | MIC2 | MIC3`，但上层 `input_channels_` 在开启参考通道时仍为 2。结合 ES7210 TDM 顺序 `MIC1, MIC3, MIC2, MIC4`，当前有中高风险只将“MIC1 + MIC3 播放参考”交给上层，而 MIC2 未进入算法链。这不解释 GPIO13 无边沿，但即使 PCM 恢复，也必须再验证产品需求是 `MR` 还是双麦加参考的 `MMR`。
- ESP32-C6 GPIO12/13 复位默认可用于 USB-JTAG，但 ESP-IDF 文档明确普通 GPIO 重配会关闭该 USB-JTAG 功能。它是需要显式固定的 pin-mux/启动约束，不是当前已证实根因。

### 3.5 2026-11-12 同板对照：先修复控制通信

无屏幕基线、旧镜像及专用仅输入镜像均未能在当前样机完成音频初始化。专用镜像的主控 I²S 内部回环通过，但 ES7210 首批寄存器写入失败；跳过启动 I²C 扫描后，PCA9557 仍有写入与读回失败，ES7210 仍无法打开。由此确认：屏幕刷新和启动扫描都不是本次控制事务失败的必要条件；本次没有有效 PCM 结果，不能用来判断 U12.11 或 R65 是否故障。

当前 PN532 的 SET0/SET1 电阻均已拆除、模式脚悬空；R8/A0 早先有跳变读数，本轮复测 A0 侧稳定 3.3 V。最小程序进一步发现地址探测稳定而寄存器事务有条件地失败，说明后续应先研究驱动事务与器件状态，不能仅把“探测到地址”当作“可正常配置”；具体是模式绑带、焊接、总线波形还是驱动时序造成的不稳定，仍未知。镜像、日志和哈希见[同板对照证据](2026-11-12-pca-audio-shared-i2c-ab-evidence.md)。

## 4. 解决方法

### 4.1 当前 PCBA 止损与判别

继续保持功放 L7 断开、GPIO23/PA_EN 关闭和扬声器空置，避免功放故障干扰诊断。当前阶段不要求 PN532 返修。按以下 Gate 顺序执行，前一级未通过时不对后一级下根因结论：

1. **控制平面：**独立 ES7210 输入程序不初始化 LCD、PN532、PCA9557 和 ES8311；I²C 100 kHz；记录每笔初始化写入，并读回 `0x00/01/02/06/08/0B/11/12/40–4C`。要求连续三次冷启动初始化完成且 `0x0B=2`。
2. **芯片脚供电与时钟：**在同一录音窗口测 U12.6/VDDP、U12.7/VDDD、U12.22/VDDA、U12.23/VDDM、U12.5/MCLK、U12.9/BCLK、U12.10/LRCK；不用 MCU 端波形代替 U12 焊盘波形。
3. **SDOUT 分段：**依次测 `U12.11 → R65 U12 侧 → R65 MCU 侧 → GPIO13`。U12.11 有波形而 R65 后无，定位焊盘/R65/过孔/走线；R65 后有波形而 DMA 固定，再查 GPIO matrix/pin mux/I²S 接收配置；U12.11 无波形且供电、时钟、状态正确，再查输出配置、芯片或装配。
4. **模拟前端：**数字输出恢复后再测 MICBIAS12、两颗麦克风 VDD、MIC1/MIC2 输入端与单麦分别启用。安静环境或单颗麦克风故障通常不足以解释 SDOUT 随 GPIO 弱拉变为全 0/全 1。
5. **产品通道契约：**先验证双槽标准 I²S 下 MIC1/MIC2，再验证四槽 TDM 逐槽数据、`MIC1 + MIC2 + MIC3` 真实内存顺序与上层 AFE 的 `MR/MMR` 契约。

保留 A/B 固件作为后续诊断工具，但主报告只以原始 PCM、SDOUT 分段波形和 TF WAV 作为结果，不以“读取 API 成功”判断录音成功。

当前不建议盲目更换 U12 或 R65。“默认无虚焊”可以用于安排软件和芯片脚测量先后，但在 U12.11/R65/GPIO13 分段波形之前，不能升级为已证实事实。

### 4.2 下一版永久修复

只把实测确认的根因转成原理图、PCB、BOM、SMT 工艺或驱动 ECO；完成双麦、播放参考、连续录音和并发测试后再纳入量产基线。

### 4.3 禁止采用的做法

- 不用 WAV 文件存在或样本“非零”代替有效音频判定；
- 不用万用表直流均值代替 I²S 数字波形；
- 在没有分段波形证据前，不把“换 U12”“恢复 L7”或“修改 PCM 后处理”定为修复方案。

## 5. 验证与关闭标准

- [ ] 固定根因、返修位置或代码差异，并用同条件 A/B 重复证明；
- [ ] 多次冷启动后 U12 状态、电源、时钟及 U12.11→GPIO13 数据链一致；
- [ ] MIC1/MIC2 原始 PCM 分别随声源变化，静音时有合理底噪，不再固定全 0/全 `-1`；
- [ ] 逐槽证明 MIC1、MIC2 和 MIC3 播放参考的真实排列，并证明上层 AFE 的 `MR/MMR` 配置符合产品要求；
- [ ] ACT_B 录音 WAV 可回放、两路对应正确，连续录音、关闭和重启后仍正常；
- [ ] 不引入 U11 发热或其它 I²C/外设回归，并保存波形、日志、样机编号和固件 SHA。
