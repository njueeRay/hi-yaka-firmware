# HiYaKa 首板麦克风无有效数据专项问题

> 编号：`HIYAKA-AUDIO-INC-001` · 首次实板发现：2026-11-04 · 本次汇总：2026-11-05 · 状态：`OPEN / 麦克风功能 FAIL`。适用对象为已拆除 L7、功放 GPIO23/PA_EN 被固件强制关闭、未接扬声器的受控开发样机。本文只讨论采集数据链；U11 异常发热、LCD 背光和 PN532 通讯各有独立问题记录。证据等级：实板短时重复实验为 L1，尚未达到麦克风功能验收。

## 1. 现象与影响

板上 `ACT_B` 可以启动和停止录音；RGB 与五颗指示灯按预期红色亮灭，TF 卡上的 WAV 文件能创建、写入并关闭。然而文件的音频峰值为 0，听不到真实环境声。早期 TDM、标准 I²S 单声道、双声道三种实板配置的原始 DMA 数据均为全 0；后续更细的 A/B 实验有时读到全 `-1`。**全 0 与全 -1 都是固定数字码值，均不能解释为正常安静环境的录音。**

已确认的边界：ES7210/U12 在 I²C 地址 `0x41` 可应答，寄存器可读；ESP32-C6 端 MCLK/GPIO0 约 4.096 MHz、BCLK/GPIO3 512 kHz、WS/GPIO12 16 kHz；DIN/GPIO13 在 20 ms 计数窗内未见上升沿。MCU 内部 I²S 回环能接收已知样本，但接入 ES7210 后，GPIO13 弱下拉可令接收码值全 0，弱上拉可令其全 -1。**当前能确定的是 MCU 没有获得有效的、由 U12 主动驱动的音频数据；不能据此认定 U12 本体损坏。置信度：高，仅限 MCU 端观察。**

这阻断双麦录音、语音对话的真实采集、播放参考与 AEC 验证；M3/M4 的录音相关验收不能勾选。扬声器功放已物理隔离，因而本问题也不能通过现场播放来听诊，TF WAV 是当前数字留样途径。

## 2. 硬件和固件连接基准

冻结的 R1.6 原理图/PCB 审计与前次活体网表显示：两颗 ZTS6216 模拟麦经 MICBIAS12 供电并进入 U12/ES7210 的 MIC1/MIC2；U12.11/SDOUT1 经 R65（51 Ω）到 ESP32-C6 GPIO13/I²S DIN。U12 的数字与模拟电源分别经过 R63/R64（设计 0 Ω）；ES7210 和 ES8311 共用 I²S 时钟。ESP32-C6 GPIO12/13 也有 USB Serial/JTAG 默认复用功能，因此路由需要实测，不能仅凭网络名确认。

旧版已验收的 S3 板同样使用 ES7210 与两颗 ZTS6216，SDOUT1 经 51 Ω 到 S3 GPIO12；旧固件管脚与旧 EDA 网表一致。它证明该类拓扑曾在另一块板上工作，**不证明当前 C6 板的器件焊接、供电和布线正确**。旧板为 24 kHz、四槽 TDM、ESP-IDF 5.4.2 体系；本次主对照是 16 kHz、双槽 16 位标准 I²S、ESP-IDF 6.1，不能把两版差异中的某一项直接指定为根因。

现场断电跨器件量测：R65 约 51 Ω，R63/R64 各约 0 Ω。这只排除了三个电阻本体的明显开路，不等于 U12 焊盘到 GPIO13 全链路导通。操作者曾在录音红灯亮时报告 R42/R45 附近约 2.83 V，但测点及四端对应关系不完整；两颗麦的供电/偏置尚未逐端确认。本轮 EasyEDA 连接器不在线，未取得新的活体 EDA 读回；不能把静态设计网表当作实板通断结论。

## 3. 排查分析：从软件到实物逐层缩小

| 顺序 | 对照或检查 | 已观察结果 | 排除了什么；还不能排除什么 |
|---|---|---|---|
| 1 | TDM → 标准 I²S 单声道 → 标准 I²S 双声道；查看原始 DMA 而非只看 WAV | 三种配置均无有效 PCM，早期记录为全 0；ACT_B 录音提示和 WAV 写盘正常 | 不是单一 WAV 写盘或按钮链路故障；仍可能是 I²S 格式、GPIO、U12 或实体电路。 |
| 2 | ES7210 I²C 寄存器读回 | `0x41` 应答；前次人工按键有屏幕实验中 `0x0B=2`，`0x12=0`、双麦选通、未静音；本轮无屏幕独立双工中 `0x0B=0`，持续 25 秒不变 | “I²C 完全不通”被排除；**状态 0/2 互相冲突，不能写成芯片始终正常，也不能写成始终关机**。I²C 成功不证明数字、模拟电源和音频脚工作。 |
| 3 | MCU 引脚活动计数 | MCLK/BCLK/WS 在主控端约 4.096 MHz/512 kHz/16 kHz；GPIO13 0 上升沿/20 ms | 主控完全未产生音频时钟的解释被排除；时钟是否到达 U12 焊盘尚未知。 |
| 4 | A：ESP32-C6 内部 I²S TX→RX 回环，避开 U12 与 GPIO13 | 已知字样接收 4096 字，命中 2048 字，`PASS`；多次冷启动重复 | 主控 I²S 接收/DMA 完全失效的解释被排除；未检验外部 DIN 线路。 |
| 5 | B：只启用 ES7210 接收，不分配 TX/ES8311；增益默认与 24 dB | `i2s_channel_read` 返回成功，但 512 字全为 `-1`，增益改变无效；等待约 10 秒仍如此 | 双工 TX/RX 配对不是唯一原因；“返回非零即录音成功”被否定。 |
| 6 | GPIO13 内部弱下拉、弱上拉对照 | 下拉时原始字全 0，上拉时全 -1，恢复浮空后值依前序状态变化 | 说明 GPIO13 电平进入当前 I²S 采样链，当前未观察到压过弱拉的有效外部驱动；**未区分 U12 不输出与 U12→MCU 中间开路**。 |
| 7 | C：完全跳过前置 A/B 的独立原双工，持续输入 25 秒 | 0.6 秒和 25.7 秒均只得固定 `-1`；`0x0B=0`，GPIO13 无边沿；弱拉结果同 B | 前置 A/B 残留和仅等待 8–10 秒不够这两种解释明显削弱；不能证明 U12 端时钟、电源或输出波形。 |

ES7210 数据手册把 `0x0B` 状态低两位的 0 定义为 power-down，2 定义为 normal。其 `0x09/0x0A` 状态周期由 LRCK 换算；当前驱动写入 `0x30`，在 16 kHz LRCK 确实到达芯片时，单阶段约 48 ms。故本轮 25 秒后仍为 0 不宜简单解释为正常启动慢；但前次同一器件曾读到 2，必须保留条件差异而继续核查。[ES7210 原厂数据手册镜像](https://files.waveshare.com/wiki/common/ES7210_DS.pdf)。

**综合判断：**当前最靠前的是“U12 未进入有效输出条件”及“U12.11 到 GPIO13 的实体链路异常”两大分支，二者均为**中等置信度的待验证假设**，没有足够证据给任何一支定责。单纯音频后处理、WAV 封装、增益设置或按键映射不足以修复当前主控端看不到的数据。

## 4. 解决方案与下一轮判别路径

### 4.1 现在可做的软件工作

1. 保存并使用独立 `hi-yaka-lab-audio-baseline` 和 `hi-yaka-lab-audio-ab` 诊断构建，分别代表无前置扰动的原双工与分层 A/B；维持 PA 关闭，不把固定 `-1` 计作录音成功。正式产品配置不运行这两段启动诊断。
2. 对照有屏幕人工录音中 `0x0B=2` 与无屏幕独立测试中 `0x0B=0` 的完整寄存器快照、初始化顺序、输入开启时长、I²C 错误和代码差异。只改变一个条件再重复；若状态稳定分流，再针对该条件设计修复。现有一次对照尚不能把 LCD 或 I²C 流量定为麦克风根因。
3. 保留原始 I²S 直读、逐通道峰值、固定码值分布、GPIO13 引脚活动以及 WAV 留样四层证据。修复后须同时看到原始 PCM 随声音变化与 WAV 内容变化，不能只看驱动 API 返回 `ESP_OK`。

### 4.2 需要维修台仪器时的最短测量顺序

下一次有示波器/逻辑分析仪及能稳定接触 QFN/0402 的夹具时，**同一录音窗口**依次记录：U12.6/VDDP、U12.7/VDDD、U12.22/VDDA、U12.23/VDDM 的实际供电；U12.5/MCLK、U12.9/SCLK、U12.10/LRCK 的实际波形；U12.11/SDOUT1、R65 两侧、MCU GPIO13 的同步波形和断电后的端到端连通。另标记并复测 MICBIAS12 与 R42/R45 四端，确认两颗麦偏置。**电压目标值以现行 EDA 电源网和原厂工作条件对照，不凭本文件臆定。**

| 测量结果 | 优先解决路径 | 复验门槛 |
|---|---|---|
| U12 某电源脚缺电、异常或时钟没到脚 | 沿对应电源/时钟网查焊点、过孔、串联器件和主控输出；修复后先确认 `0x0B` 稳定进入正常状态 | 芯片脚电源/时钟符合设计，再读原始 PCM。 |
| 电源与时钟到脚，`0x0B` 仍长期为 0 | 同条件对照驱动寄存器写入和复位/开关时序，再检查芯片焊接；软件差异可重现时修驱动，仍失败时考虑 U12 更换 | 多次冷启动状态正常，SDOUT1 有受控输出。 |
| `0x0B=2` 且 U12.11 无数据波形 | 先核对 `0x12` 的 SDOUT1 三态位、slot/主从与 MICBIAS，再看 U12 焊接/器件；不能只凭 0x0B 判芯片健康 | 在已知声音输入下 U12.11 有随声音变化的数据。 |
| U12.11 有波形、R65 后或 GPIO13 没有 | 修复 U12→R65→GPIO13 的焊盘、串阻、过孔或走线；R65 本体 51 Ω 不能替代端到端检查 | MCU GPIO13 同步看到数字波形，原始 RX 不再受弱拉决定。 |
| GPIO13 有波形、原始 RX 仍固定码值 | 回查 C6 GPIO matrix、I²S DIN 指派、USB Serial/JTAG 复用、slot/位宽和采样对齐 | 原始 RX 能对已知音频产生动态样本。 |
| 数字链路有动态数据但两颗麦仍无声音 | 逐查 MICBIAS12、两颗麦供电/焊接和 CH1/CH2 模拟输入 | 两路独立麦克风响应与物理声源一致。 |

若现场仍只有万用表，最多先确认可安全触及的直流供电和断电端到端连通。**万用表的直流平均值不能判定 512 kHz 数据脚有没有正确串行音频**；不要求操作者在密集焊盘上盲探、飞线或替换芯片。

### 4.3 关闭条件

- [ ] 找到可重复、能区分软件配置与实物电路的根因证据，并记录改动及返修位置；
- [ ] 修复后多次冷启动，ES7210 状态、实际供电/时钟与 SDOUT1→GPIO13 数据链一致；
- [ ] MIC1/MIC2 原始 PCM 均随各自声源变化，静音时有合理底噪，不再固定全 0/全 -1；
- [ ] ACT_B 启停与 TF WAV 文件可回放，两路对应关系、连续录音及关闭文件均实板复验；
- [ ] 复测不引入 U11 功放发热、I²C 总线异常或其它外设回归，再按固件 PRD 的 M3/M4 验收逐项勾选。
