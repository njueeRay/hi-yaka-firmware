# 专项问题分析：HiYaKa PN532 无 I²C 应答

> 问题编号：`HIYAKA-NFC-INC-001`<br>
> 级别：`P1`<br>
> 首次确认：2026-11-04<br>
> 影响范围：HiYaKa R1.6 原开发样机；2026-11-05 换入样机复现，PCB 修订未独立核对<br>
> 当前状态：PN532 在预期地址始终 NACK，根因未确认，NFC 功能 `FAIL`

## 1. 结论

- **已确认：**主 I²C 总线可访问 PCA9557、ES8311、ES7210、QMI8658A；PN532 在预期 7 位地址 `0x24` 从冷启动起持续不应答，固件版本请求无法进入协议层。
- **已确认：**C108 所在 VREF 网和 `RES&OFF` 复位网在上电时均约 3 V；无屏幕固件观察 240 秒仍 NACK。因此“完全没电”“一直被复位拉低”和“仅由屏幕初始化导致”都不足以解释现象。
- **未知：**PN532 的实际供电条件、27.12 MHz 晶振、模式绑带、SDA/SCL 到芯片焊盘的波形、器件焊接与电源拓扑是否满足原厂要求，均未完成实物闭环。**当前没有已证实根因；置信度：未知。**
- **决策：**已物理隔离功放的样机可继续非 NFC 测试（`CONDITIONAL GO`）；NFC 功能与整机发布 `NO-GO`，M5 NFC 验收不关闭。

## 2. 现象

冷启动 I²C 全地址扫描只见 `0x18/0x19/0x41/0x6B` 四个已知器件，未见 PN532 的 `0x24`。固件的唤醒、延时探测及版本请求均失败。停用 ST7789/PARLIO 的无屏幕对照镜像保持运行 240 秒，PN532 仍从冷启动 NACK；其他四个固定地址继续应答。操作者在 MASTER ON 时量得 PN532 附近 C108 非接地端约 3 V，`RES&OFF` 节点约 3 V。当前无 PN532 芯片脚、晶振、SDA/SCL 波形的实测。

2026-11-05 换入样机从空 Flash 烧录后，在有屏幕及无屏幕两版实验固件中均复现 `0x24` NACK；三次固件版本请求均失败，其他四个器件继续应答。这是另一块实板的复现证据，但新板未重复测量 C108、复位网或芯片脚，因此不能把原开发样机的电压数据直接套给新板。

## 3. 排查分析

R1.6 原理图/PCB 与前次活体网表均把 U13.27/SCL 接主控 GPIO11、U13.28/SDA 接 GPIO10；R74/R73 将 I1/I0 设为 `10`，设计意图为 I²C 模式；`RES&OFF` 经 R71 上拉、R75 下拉。PCB 两脚网络与原理图一致，可排除设计数据中显性的 SDA/SCL 对调或未布线，不能替代成品板端到端连通与波形确认。

U13.40/VBAT 接 `SYS_3V3`，U13.23/PVDD 和 U13.39/DVDD 同属 `VREF`，与原厂典型供电图不同。但 C108/VREF 实测约 3 V，不能直接断言芯片未供电，**也不能把该非典型连接直接认定为 NACK 根因**。I²C 其它器件正常说明主控与公共总线基本工作，但不能证明 U13 焊盘、晶振或该器件的供电/模式正确。无屏幕对照削弱了 LCD 初始化是必要条件的假设，不能证明显示流量与所有 I²C 间歇错误完全无关。

| 待验证分支 | 当前证据强弱 | 最短判别方法 |
|---|---|---|
| 晶振未起振、模式绑带错误或复位时序不满足 | 设计网络已核对，芯片端波形未知 | 上电同一窗口量 27.12 MHz 晶振、I1/I0 与 RSTPD_N 引脚实际电平。 |
| U13 接口脚未收到 I²C 或焊接异常 | 主总线其它器件应答，U13 焊盘未知 | 比对 GPIO10/11 与 U13.27/.28 的 SDA/SCL 波形、ACK 时隙及断电连通。 |
| 电源拓扑或实装供电异常 | VREF/复位网约 3 V，单点电压不足以闭环 | 测 VBAT、PVDD、DVDD 与各地脚实物电压，按 PN532/C1 数据手册核对。 |
| 软件地址/唤醒问题 | 已做全地址扫描、启动和延时探测，优先级较低 | 在硬件波形成立后对照原厂 I²C 唤醒、地址位宽和复位时序。 |

## 4. 解决方法

1. **当前样机：**保留 NFC 能力降级，继续运行其它模块；不把 `0x24` NACK 解释为“未读到标签”。在具备夹具的维修台，按“电源/复位/绑带 → 晶振 → U13 SDA/SCL → 接口 ACK”顺序测，先找第一个与设计不符的节点，再做定点返修。
2. **下一版永久修复：**若实测证实电源、绑带、时钟或布线问题，按根因修改原理图与 PCB，并同步 SMT 装配检查、固件时序及回归测试；若现行 PVDD/DVDD 连接无法满足原厂条件，应按 PN532/C1 推荐供电图重新设计并做样机 A/B，而非仅凭静态网表改板。
3. **不能采用：**不得直接把 `VREF` 短接到 `SYS_3V3`，因为 DVDD 是稳压器输出，存在反向供电风险；不得用不断增加软件超时来掩盖持续 NACK；不能在没有接口应答时宣称 NFC 标签功能已验证。

## 5. 验证与关闭标准

- [ ] 同一样机记录 VBAT/PVDD/DVDD、RSTPD_N、I1/I0、晶振和 SDA/SCL 的实测，并解释首次 NACK 的根因；
- [ ] 修复后多次冷启动及 240 秒运行中，`0x24` 稳定 ACK、固件版本和 SAM 初始化成功；
- [ ] 使用实际标签重复完成 ISO14443A 寻卡/UID 读取、超时/取消和 RF 关闭，并记录无标签场景；
- [ ] 复测与 LCD、音频及其它 I²C 器件并发，保留原始日志、波形、样机编号、固件 SHA 与返修位置；满足后再评估 M5 和发布门禁。
