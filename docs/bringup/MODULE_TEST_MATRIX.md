# HiYaKa 模块测试矩阵

## 1. 共通记录要求

每次测试记录样机编号、硬件 revision、固件/上游 SHA、构建容器 digest、环境、步骤、期望、实测、原始日志、结论、缺陷 ID 和复测条件。功能通过必须同时具备正常路径、关键异常路径和恢复路径；一次成功现象不算稳定性证据。

## 2. 模块矩阵

| 模块键 | 主要接口 | 最低等级 | 核心场景 | 必取原始证据 | 主要通过条件 |
|---|---|---:|---|---|---|
| `power` | MASTER_SW / 3.3 V | L1 | 分级限流、冷启动、复位、异常停止 | 电流/电压 CSV、波形、照片/视频 | 无异常发热或持续限流；关键轨和复位可解释 |
| `flash` | UART0 / SPI0/1 | L1 | 枚举、读取、烧录、校验、三次冷启动 | 烧录与启动完整日志、产物 SHA | 16 MiB DIO 和候选身份匹配；无重启循环 |
| `i2c` | GPIO10/11, 100 kHz | L1 | 五地址扫描、NACK、超时与恢复 | 串口日志、逻辑分析仪捕获 | 地址行为符合装配；失败可降级且有界 |
| `pca9557` | I²C `0x19` | L1 | `0x40`→`0x38`→回读、故障注入 | 总线捕获、寄存器日志、输出状态照片 | 顺序和值正确；危险输出保持关闭 |
| `display` | ST7789 200×320 | L2 | 方向、色阶、边界、刷新、低电亮度 | 测试图照片/视频、SPI/复位波形 | 方向颜色正确，无明显花屏/撕裂，首帧后开背光 |
| `input` | DPAD ADC / GPIO22/5 | L2 | ADC 分布、迟滞、去抖、长按、连按、组合 | 原始 ADC CSV、事件日志、交互录像 | 映射稳定；窗口可量化；无明显误触 |
| `audio` | ES7210/ES8311/I²S/PA | L2 | 双麦、参考通道、播放、并发、启停爆音 | 寄存器、I²S 波形、原始 PCM、播放录音 | 通道可解释，采播稳定，无不可接受爆音或丢帧 |
| `storage` | TF SDSPI | L2 | 无卡/插拔/慢卡/满卡/坏卡/掉电/长录音 | 文件系统日志、文件哈希、恢复前后目录、录音样本 | 不阻塞音频；文件可恢复或明确失败 |
| `nfc` | PN532 `0x24` | L2 | 多类标签、重复读取、超时、读距、金属环境 | 标签清单、时间戳日志、距离数据、录像 | 只读结果可重复，超时可退出，不阻塞主交互 |
| `imu` | QMI8658A `0x6B` | L2 | ID、零偏、六面、轴向、量程、采样率 | 原始 IMU CSV、装配方向照片 | 轴向一致，零偏/噪声可解释，轮询有界 |
| `feedback` | GPIO8/21 / PCA IO2 | L2 | 单灯、五灯、亮度限制、马达短脉冲、电源扰动 | 录像、波形、电流记录 | 默认关闭；反馈正确；不掉压/复位 |
| `battery` | GPIO2 ADC | L2 | 多点标定、充放电、低电、显示误差 | 外部仪表+ADC CSV、拟合结果 | 误差可量化；不把电压单点当作充满信号 |
| `network` | 2.4 GHz Wi-Fi | L2 | 首次配网、重连、弱网、断网、服务超时 | 状态机日志、抓包/网络条件、资源趋势 | 失败可见可恢复，不破坏本地录音或泄漏资源 |
| `ota` | 双 OTA / NVS | L3 | 正常升级、坏包、断网、未确认首启、回滚 | 两槽版本、启动日志、包哈希、回滚与数据校验 | 错包拒绝，未确认可回滚，录音/配置一致 |
| `long_run` | 全系统 | L3 | Wi-Fi+显示+音频+TF 并发、温升、功耗、长稳 | 持续日志、功耗/温度/内存趋势、复位统计 | 批准时长内无不可恢复错误，趋势可解释 |

## 3. 故障优先级

- P0：可能损坏硬件、数据或形成安全风险；立即停止对应实验；
- P1：主路径不可用、重启循环、数据破坏或无法回滚；不得关闭对应里程碑；
- P2：存在可控降级或局部交互问题；必须有边界、Owner 和复测条件；
- P3：不影响主要验收的可维护性或体验问题；进入版本计划。

`FAIL/BLOCKED` 必须在模块 JSON 和 `defects.md` 中使用同一个缺陷/阻塞项 ID。修复后创建新的测试记录，不把旧 `FAIL` 直接改成 `PASS` 来抹掉历史。
