# YaKa 证据与事实治理

## 1. 证据优先级

活体 EDA/制造数据 > 冻结审计 > 批准 PRD > 厂商/官方 SDK > 本仓库设计与测试 > 历史资料。截图、编译通过和单次现象不能单独证明硬件或产品能力。

## 2. 证据等级

| 等级 | 含义 | 允许结论 |
|---|---|---|
| L0 | 静态检查、host tests、可复现构建、产物哈希 | 软件基线成立 |
| L1 | 目标板启动、总线和器件基础日志 | 板级接口可进入功能验证 |
| L2 | 功能链路、重复性、异常与恢复 | 该功能实板通过 |
| L3 | 整机压力、功耗、温升、声学、长稳、OTA | 可进入发布判断 |

## 3. 实验记录最小字段

时间、操作者、Git SHA、上游 SHA、ESP-IDF/容器 digest、硬件 revision/样机编号、配置、步骤、原始日志、产物哈希、期望、实测、结论、缺陷 ID 和复测条件。

## 4. 结论规则

- `GO`：请求阶段无未关闭 P0/P1；
- `CONDITIONAL GO`：无 P0，存在边界明确且有截止条件的 P1；
- `NO-GO`：存在 P0、未解释一致性差异或关键检查缺失；
- `skipped` 不是 pass；`degraded` 必须说明近似方法和补测计划。

## 5. 保留策略

原始日志和附件只追加、不静默改写；修订通过新版本和 SHA-256 追踪。涉及用户内容的录音不提交 Git，只保存匿名化指标、短诊断样本的授权路径和哈希。
