# 专项问题分析：<问题名称>

> 问题编号：`<ID>`<br>
> 级别：`P0 / P1 / P2`<br>
> 首次确认：YYYY-MM-DD<br>
> 影响范围：<版本、批次或样机><br>
> 当前状态：<一句话说明>

## 1. 结论

用业务人员能理解的语言回答：

- 问题是什么；
- 是否影响继续测试、制造或发布；
- 已确认的根因是什么；
- 当前决定是 `GO / CONDITIONAL GO / NO-GO` 中的哪一种。

结论先写事实，再写推断；推断必须标明置信度。

## 2. 现象

只记录可观察事实：发生条件、样机/版本、实际表现、复现次数和关键测量。不要在本节混入根因猜测。

## 3. 排查分析

说明证据如何支持或排除各个原因。只保留会影响判断的技术细节；必要时使用短表格或简短计算。

## 4. 解决方法

分别说明：

1. 当前样机如何止损或恢复开发；
2. 下一版如何永久修复；
3. 哪些临时方案明确不能采用。

## 5. 验证与关闭标准

列出可执行、可测量的复测步骤，以及什么条件满足后才能关闭问题或解除发布阻断。

## 6. 证据来源

列出原理图/PCB 位置、实测记录、器件数据手册和其他直接支持结论的资料。

---

写作约束：正文优先控制在 2–4 页；结论不超过 6 条；不重复聊天过程；不堆叠与决策无关的背景；“已确认、推断、未知”必须分开表达。
