# HiYaKa 固件项目任务书

> 状态：工作基线 v1.0  
> 日期：2026-10-29  
> 当前阶段：PH0–PH5 与 M2–M6 软件 L0 已就绪；当前开发样机已拆除 L7，等待操作者返回后受控恢复非功放 M1

## 1. 北极星目标

在 HiYaKa 硬件上形成一套可复现、可审计、可恢复的产品固件：可靠完成 Wi-Fi 配网和 AI 语音对话，快速开始并安全保存本地录音，通过非触控屏幕和实体按键提供清晰交互，并将掉电、断网、无卡、满卡、外设故障和 OTA 失败处理为可理解的终态。

## 2. 当前范围

- ESP32-C6 / ESP-IDF 6.1 / 16 MiB Flash / 无 PSRAM；
- AI 对话、播放与打断；
- 本地录音、TF 文件、掉电恢复；
- LCD、实体键、RGB、振动和电量估算；
- NFC 只读、IMU 基础能力；
- 诊断、用户确认 OTA 和失败回滚；
- GitHub 私有开发仓库、`ChatChatTech/yaka/firmware` 公开发布快照、`aliyun_raynode` 可复现构建、本地与飞书文档治理。

## 3. 非目标

HiYaKa 不实现 4G/SIM、5 GHz Wi-Fi、主动式蓝牙音频、摄像头、触摸或游戏。未批准的按键语义、录音格式和 NFC 业务不能由代码先行冻结。

## 4. 完成定义

“完成”不是编译通过。每个核心链路必须具备精确 Git/SDK/硬件版本、可重复步骤、原始日志、产物哈希、故障注入结果和实板复测证据。量产发布还必须覆盖整机功耗、温升、声学、弱网、随机硬切电源和 OTA 回滚。

## 5. 决策权限

Owner 冻结产品目标、根本硬件变更、不可兼容协议/格式、量产安全和不可逆操作。Agent 在批准路线内自主实现、构建、可恢复验证、证据整理、上游同步和文档维护；遇到产品 `TBD` 或权威资料冲突时不得代替 Owner 决策。

## 6. 工作分工

- 私有 GitHub `origin` 保存完整开发历史、产品差异和治理文档；`upstream` 跟踪小智发布版本；
- `ChatChatTech/yaka/firmware` 只保存通过公开边界审查的固件快照；
- `aliyun_raynode` 固定 ESP-IDF 6.1 完成可复现构建；
- 本地电脑负责代码审阅、飞书同步和真实硬件串口/烧录入口；
- EasyEDA Pro 活体工程和冻结制造包负责硬件真值；
- 飞书负责团队阅读、日志协作和附件入口，Git Markdown 负责审计和变更历史。

## 7. 双仓库发布模型

- 私有开发真值：`njueeRay/hi-yaka-firmware`，保留完整历史、开发分支、内部 PRD、飞书登记和硬件/制造资料；
- 公开产品仓库：`ChatChatTech/yaka`，固件固定发布到 `/firmware`，未来应用使用其他顶层目录；
- 公开方式：发布经过审查的树快照，不做 Git subtree、mirror 或私有历史迁移；
- 每个公开快照记录私有来源 SHA、上游 SHA、ESP-IDF、证据等级、公开排除项和许可证；
- 当前公开提交：`ChatChatTech/yaka@0489e83`；本轮 PN532/QMI8658A、WAV 与事故处置仍在私有 PR #15，尚未发布公开快照；
- 历史 `ChatChatTech/yaka-firmware` 继续只作为历史资料，不覆盖、不改写。

## 8. 当前硬件与制造状态口径

- 原理图、PCB 与静态 DRC 的封存审计已经完成，但两块样机随后取得 U11/BOOST 快速异常发热的实板 `FAIL` 证据；旧 `GO TO PROTOTYPE` 已被 `HIYAKA-HW-INC-001` 覆盖；
- 当前开发样机拆除 L7 后不再快速升温，只允许在操作者在场、PA 硬禁用、扬声器断开和持续温度监测下恢复非功放验证；操作者离场时保持 MASTER OFF；
- 扬声器播放和下一版制造为 `NO-GO`，直到 U11 CTRL 默认态、BOOST 电感选型、保护设计及复测证据闭环；
- 2026-11-01 撤销 LED2 极性与 CPL 坐标的工程 `HOLD`：当前 EDA 渲染的极性位置、方向和已读取坐标均经人工确认正确；
- SMT 订单平台曾需要手工 DFM 调整，正式制造证据仍须保存最终订单预览、DFM 结果和人工签核；
- LED2/CPL 不是当前阻断项，但也不能用其已关闭状态覆盖新的功放电源安全 P0。
