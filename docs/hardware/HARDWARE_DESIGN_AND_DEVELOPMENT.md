# 1. 项目规划

## 1.1 目标

YaKa 3.0 的目标不是“让一块 ESP32-C6 板跑起来”，而是形成一套可复现、可诊断、可恢复的随身 AI 设备工程基线：稳定完成本地交互、语音采集与播放、Wi-Fi AI 对话、TF 本地录音、NFC/IMU 辅助感知、电源管理和受控 OTA，并把断网、无卡、满卡、外设缺失、随机硬切电源和升级失败处理成可理解、可恢复的产品状态。

当前没有批准的量产日期。排期以 Gate 和证据等级驱动，不能用日历日期替代硬件到板、功能闭环或稳定性证据。

### Stage 0｜历史 YaKa 固件与旧资料（归档阶段）

- `ChatChatTech/yaka-firmware` 只作为历史线索，不再承担 YaKa 3.0 主开发；
- 旧编译环境、旧上游版本、旧引脚和旧交互不得直接继承；
- 历史材料只有经过 R1.6 硬件、当前产品需求和实板证据复核后，才能进入现行基线。

### Stage 1｜YaKa 3.0 工程基线与首板启动（当前阶段）

当前出口是取得“软件可构建 + 首板可安全上电 + 基础总线可诊断”的最小闭环，而不是提前接入所有外设。

已完成：

- 小智 `v2.5.2` / `49b4380` 固定为首个上游基线；
- ESP-IDF 6.1 开发环境和 Raynode 远程构建基线建立；
- `chatchat/hi-yaka-v3` 板型、ESP32-C6、DIO、16 MiB Flash、无 PSRAM 编译策略建立；
- M1 完整构建和 7 项聚焦测试通过，属于 L0 软件证据；
- R1.6 原理图/PCB全链路复审完成，结论为 `GO TO PROTOTYPE`；制造发布保持 `CONDITIONAL GO`。

Stage 1 退出条件：

- 限流上电、3.3 V、电源开关、静态电流无阻断异常；
- USB/串口、BOOT/RESET、下载和启动日志可重复；
- Flash ID、容量、擦写和 DIO 模式与硬件一致；
- I²C0 在 100 kHz 下发现五个预期地址；
- PCA9557 先写安全锁存、再切换方向并完成 readback；
- 每块样机记录硬件版本、SN、固件提交、原始日志和异常项。

### Stage 2｜核心设备能力闭环

这一阶段对应 M2–M5，目标是把“板级可启动”推进到“核心产品链路可工作”。

- M2：LCD、实体键、RGB、五灯链、振动和基础 UI 状态；
- M3：ES7210/ES8311、双麦与播放参考、I²S、功放时序、播放和录音；
- M4：TF 挂载、流式写入、文件提交、满卡和随机硬切恢复；
- M5：Wi-Fi 配网、鉴权、AI 对话、打断、弱网重连和服务端 AEC/半双工边界。

Stage 2 退出条件不是“单次演示成功”，而是每个模块拥有 L2 功能证据、异常恢复证据和可重复测试步骤。

### Stage 3｜系统整合与受控发布

这一阶段对应 M6–M7，覆盖 NFC 只读、IMU、电量与充电提示、受控 OTA/回滚、整机并发、功耗、温升、声学、长稳和发布证据。

最终发布必须明确区分：工程样机、受控演示、EVT 可验证版本和量产候选。当前项目尚未进入量产发布判断。

### 当前七条工作轨道

- **硬件与制造线：**冻结 R1.6 基线，生成并签核唯一 Gerber/Drill/BOM/CPL，处理采购、客供、SMT、总装和逐板追溯。
- **平台与上游线：**以 ESP-IDF 6.1 和小智固定 tag 开发，使用独立同步分支吸收上游更新，不让上游滚动改动冲击产品主线。
- **交互与反馈线：**建立 LCD、按键、RGB、五灯链和振动的状态表达；按键语义未获产品批准前不由驱动代码擅自冻结。
- **音频与 AI 对话线：**验证双麦、播放参考、codec、PA、LiteAudioEngine 和服务端链路；C6 无设备侧成熟 AEC，不虚构全双工免提能力。
- **录音与数据线：**TF 上采用流式、有界缓冲和可恢复提交；录音格式、命名、保留策略和导出方式仍需产品冻结。
- **电源、OTA 与可靠性线：**把 MASTER_SW 硬切、掉电恢复、电池估算、弱网、外设缺失和 OTA 失败纳入正常状态机。
- **产品、软件应用与文档线：**固件 PRD、产品手册、未来应用 PRD 分开维护；主文档只保存跨域结论、项目索引和连续日志。

### 当前阶段明确边界

当前可以声明：M1 软件基线已建立、IDF 6.1 构建通过、硬件接口契约已进入首板验证。

当前不能声明：LCD/音频/TF/NFC/IMU/电源/OTA 已实板通过，设备侧 AEC 已具备，整机功耗和声学已达标，或制造包已无条件发布。

# 2. 技术链路

## 2.1 当前版本与工程原则

- **硬件基线：**YaKa v3.0 / R1.6；原理图和 PCB 可以进入打样，制造文件仍需最终签核。
- **固件基线：**`hi-yaka-firmware`，小智 `v2.5.2`，ESP-IDF 6.1，板型 `chatchat/hi-yaka-v3`。
- **资源原则：**ESP32-C6 无 PSRAM；所有队列、音频缓冲、显示缓冲和文件写入必须有界并可测。
- **上游原则：**小智提供平台能力，不定义 YaKa 产品行为；产品差异收敛在 board、适配层和领域服务。
- **数据原则：**I²S RX 只有一个所有者，本地录音在采集适配层分流；TF 写入不能阻塞音频实时路径。
- **状态原则：**只有一个产品状态协调者；ISR、驱动和后台任务只发布事件，不直接改 UI 或产品状态。
- **证据原则：**构建属于 L0；板级、功能和系统结论分别要求 L1、L2、L3 证据。

真正需要闭合的不是某个驱动，而是下面的完整链路：

```text
产品需求与交互
→ 原理图 / PCB / BOM / SMT / 总装
→ 限流上电 / 串口 / Flash / I²C
→ 显示 / 输入 / 灯光 / 振动
→ 双麦采集 / 播放参考 / codec / PA
→ TF 流式录音 / 文件恢复
→ Wi-Fi / AI 协议 / 音频上下行
→ NFC / IMU / 电量 / OTA
→ 整机功耗 / 温升 / 声学 / 长稳
→ 受控发布与后续应用协同
```

## 2.2 系统组成

| 模块 | 当前方案 | 在产品链路中的作用 | 当前验证状态 |
|---|---|---|---|
| 主控 | ESP32-C6 | Wi-Fi、协议、音频调度、UI 与整机控制 | L0 构建通过 |
| 程序存储 | PY25Q128HA，16 MiB，DIO | 程序、双 OTA、资源和配置 | 待 L1 核验 ID/容量 |
| 显示 | H0160S002 V1 / ST7789，200×320，非触控 | 状态、菜单、错误和恢复提示 | 待 G2 |
| 输入 | ADC DPAD + ACT/PWR | 实体导航和确认 | 待实板阈值标定 |
| 音频采集 | ES7210 + 双模拟麦 + 播放参考 | 对话和本地录音 | 待 G3 |
| 音频播放 | ES8311 + HT8691R + 8 Ω/1 W 扬声器 | 语音、提示音和播放参考 | 待 G3 |
| 本地存储 | TF / SDSPI | 录音文件、异常恢复和导出 | 待 G4 |
| NFC | PN532 / I²C，无 IRQ/独立复位 | 首发只读情境入口 | 待 G6 |
| IMU | QMI8658A / I²C，无 IRQ | 基础动作感知 | 待 G6 |
| 扩展 IO | PCA9557 | LCD、马达等安全控制 | L0 静态合同，待 L1 |
| 反馈 | 单 RGB、五灯链、3 V ERM | 可见/触觉状态反馈 | 待 G2 |
| 电源 | MASTER_SW、LGS4056H、BAT ADC | 硬切电源、自治充电和电压估算 | 待 G1/G6 |

## 2.3 硬件—固件关键契约

共享 I²C0 使用 GPIO10 SDA、GPIO11 SCL，首板为 100 kHz：

| 器件 | 7-bit 地址 | 约束 |
|---|---:|---|
| ES8311 | `0x18` | 播放 DAC，实板 probe |
| PCA9557 | `0x19` | 先写 Output=`0x40`，再写 Configuration=`0x38`，最后 readback |
| PN532 | `0x24` | I²C 轮询，必须有超时和总线恢复 |
| ES7210 | `0x41` | 双麦及播放参考，slot 必须用原始 PCM 确认 |
| QMI8658A | `0x6A` | SA0 已固定，当前仅轮询 |

其他必须显式遵守的接口：

- LCD 实际端点是 GPIO6 MOSI、GPIO7 SCLK，不能被历史错误网名反向误导；
- TF 使用 GPIO18 MOSI、GPIO19 CLK、GPIO20 MISO、GPIO15 CS，无 card-detect；
- ES7210/ES8311 共用 MCLK/BCLK/WS，播放和采集 slot、位宽、主从关系必须冻结；
- HT8691R 必须在 DAC/I²S 稳定后使能，停播时先关 PA；
- MASTER_SW 为物理硬切，固件不能依赖“总能执行关机回调”；
- MCU 目前只能从 BAT ADC 估算电压，不能宣称可观测完整充电终态。

详细逐网、PCB、制造和风险论证不在主文档重复，统一从第 3 节进入专项材料。

# 5. 附录

## 5.1 参考资源与事实优先级

事实优先级依次为：

1. 当前 EasyEDA Pro 活体工程、绑定 PCB、BOM、DRC 和结构化端点；
2. R1.6 最终复审和冻结制造包；
3. 批准版 YaKa 产品需求；
4. 精确料号厂商资料、ESP-IDF 官方资料和小智固定版本源码；
5. 本仓库架构、测试与文档；
6. 历史仓库、截图和社区资料，仅用于发现线索。

冲突时保留冲突，并由更高优先级资料和实验解决。不得以“文档更新更晚”代替事实裁决。

## 5.2 研发成本与资源

当前尚未形成经批准的研发预算和付款 Gate。主文档只记录已经获得凭据的样机、SMT、采购、服务器、测试仪器和认证成本；估算值与实际支出必须分列，供应商报价必须标注日期和有效期。

当前关键资源包括：

- YaKa 3.0 首板及可追溯样机；
- Raynode ESP-IDF 6.1 远程开发环境；
- 本地烧录、串口、示波器/逻辑分析、电子负载或等效测量条件；
- 音频假负载、扬声器和声学测试环境；
- TF、NFC 标签、充电/电池和故障注入工具。

## 5.3 工程备份与恢复

- 活体 EasyEDA 工程负责当前硬件真值；冻结制造包和审计附件负责阶段证据；
- Git 私有仓库负责开发历史，公开仓库只接收审查后的发布快照；
- 飞书附件使用 SHA-256 和文件 Token 登记，不静默替换；
- 固件构建记录应保留 Git SHA、上游 SHA、IDF 版本、容器 digest、配置和产物哈希；
- 任何迁移、导出或重新生成都必须可追溯到来源版本。
