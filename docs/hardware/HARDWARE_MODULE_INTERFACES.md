# YaKa 3.0 硬件模块连接与固件接口契约

> 适用硬件：YaKa 3.0 / R1.6  
> 基准日期：2026-10-29  
> 文档性质：固件开发入口，不替代原理图、PCB、器件规格书和实板证据  
> 证据等级：连接关系主要为 L0 静态审计；标为“待 L1”的项目不得宣称实板通过

## 1. 使用方式与事实边界

本文件把固件最常使用的硬件事实收敛为一份接口契约：模块接到哪里、由谁控制、上电默认态是什么、驱动必须遵守什么顺序、还欠什么实板证据。它解决的是“开发时去哪里查接口”，不把详细审计过程复制成第二份硬件真值。

事实冲突时按以下顺序裁决：EasyEDA Pro 活体工程与冻结制造包 → R1.6 最终复审 → 精确料号资料 → 本文件。任何引脚、地址或极性变化，必须先修改硬件事实源，再同步本文件和板级配置。

状态标记：

- **L0 已确认**：原理图、PCB、网表、源码或构建层面的静态证据已闭合；
- **M1 已实现**：当前固件已经编码，但尚不代表实板通过；
- **待 L1/L2**：必须在样机上取得串口、逻辑分析仪、示波器、音频、文件或交互证据。

## 2. 系统连接总览

```text
USB-C ─ CH340K ─ UART0 / 自动下载 ─┐
16 MiB SPI Flash ─ SPI0/1 ────────┤
                                   │
                              ESP32-C6
                                   │
        ┌──────── I²C0 GPIO10/11 ──┼─ ES8311 / PCA9557 / PN532 / ES7210 / QMI8658A
        │                          │
        ├──────── I²S ─────────────┼─ ES7210 双麦+播放参考 / ES8311 播放
        │                          │                    └─ HT8691R ─ Speaker
        ├──────── LCD SPI ─────────┼─ ST7789 200×320（CS/DC/RST/BL 经 PCA9557）
        ├──────── SDSPI ───────────┼─ TF Card
        ├──────── GPIO/ADC ────────┼─ DPAD / KEYA / KEYB / BAT ADC
        └──────── GPIO/RMT ────────┴─ 单 RGB / 五灯链

PCA9557 ─ LCD_BL / LCD_RST / MOTOR_CTRL / LCD_CS / LCD_DC
MASTER_SW ─ 物理切断整机输入电源；不是可由固件保证执行回调的软关机
```

## 4. I²C 总线与固定地址

I²C0 使用 GPIO10 SDA、GPIO11 SCL，3.3 V 上拉，首板从 100 kHz 开始。驱动不得自行重建总线或无限阻塞；所有事务必须有超时，错误恢复必须受统一总线层控制。

| 器件 | 7-bit 地址 | 用途 | 接口限制与验证要求 |
|---|---:|---|---|
| ES8311 | `0x18` | 播放 DAC | probe、寄存器 readback、静音/解除静音顺序、爆音验证 |
| PCA9557 | `0x19` | LCD、马达和历史电源链控制 | 必须先写 Output=`0x40`，再写 Configuration=`0x38`，最后 readback |
| PN532 | `0x24` | NFC，只读情境入口 | I²C 模式 `I1:I0=10`；无 IRQ、无独立复位，必须轮询、超时和可退出 |
| ES7210 | `0x41` | 双麦及播放参考采集 | 芯片初始化、slot/位宽/通道映射必须用原始 PCM 实测确认 |
| QMI8658A | `0x6A` | IMU | SA0 已固定；无 IRQ，采用有界轮询，不承诺深睡手势唤醒 |

### 4.1 PCA9557 安全态

| IO | 当前连接 | 启动策略 |
|---:|---|---|
| IO0 | LCD_BL | 输出，默认关闭，屏初始化完成后最后开启 |
| IO1 | LCD_RST | 输出，按 ST7789 时序复位 |
| IO2 | MOTOR_CTRL | 输出，默认关闭，只允许有界短脉冲 |
| IO3 | NC | 保持输入，可作为未来受控扩展，未经 ECO 不使用 |
| IO4 | 历史 `PWR_EN` 链路 | M1 保持输入；软保持链路未成立，禁止宣称受控软关机 |
| IO5 | NC | 保持输入，可作为未来受控扩展，未经 ECO 不使用 |
| IO6 | LCD_CS | 输出，上电/初始化保持未选中；安全输出字节中置高 |
| IO7 | LCD_DC | 输出，事务边界内受 LCD 驱动控制 |

启动时必须执行：

1. 写 Output Port `0x40`，先锁存安全输出值；
2. 写 Configuration `0x38`，仅把 IO0/1/2/6/7 切为输出；
3. 回读 Output/Configuration；不一致时进入可诊断降级态，不反复重启；
4. 在 PCA9557 安全态成立前，禁止初始化 LCD 背光和马达动作。

## 5. 显示、输入与反馈

### 5.1 ST7789 显示

- 型号：H0160S002 V1，ST7789，200×320，非触控；VDD/IOVCC 均为 3.3 V；
- SPI 数据：GPIO6 MOSI、GPIO7 SCLK；CS/DC/RST/BL 由 PCA9557 控制；TE 未连接；
- 固件顺序：PCA9557 安全态 → LCD 复位 → SPI/面板初始化 → 首帧完成 → 最后打开背光；
- 显存必须采用有界分块/行缓冲，不能假设 PSRAM 或全屏双缓冲；
- L1/L2 必须验证方向、颜色格式、刷新撕裂、低电量亮度和批次亮度。

### 5.2 实体输入

- DPAD：GPIO4 ADC 电阻梯，必须建立实板采样分布、窗口、迟滞、去抖和多键异常策略；
- KEYA/KEYB：GPIO22/GPIO5，外部晶体管反相拉低，固件启用上拉并去抖；
- PWR_A/PWR_B：当前仅可作为整机已上电后的快捷键语义；MASTER_SW 关闭时不能靠它们唤醒；
- 所有按键只发布输入事件，由唯一产品状态协调者决定 UI/录音/对话行为。

### 5.3 RGB 与振动

- GPIO8 驱动单颗 RGB，GPIO21 驱动五颗串联 RGB；上电默认关闭并限制总亮度；
- 马达为 3 V ERM `LCM0720A3176F`，经 Q9 低侧开关、PCA9557 IO2 控制；不是 LRA，禁止套用共振驱动算法；
- 马达动作必须有最大持续时间和错误兜底，首板先短脉冲并监测 3.3 V 轨。

## 6. 音频链路

```text
Mic L ─┐
       ├─ ES7210 CH1/CH2 ─ SDOUT1/GPIO13 ─ ESP32-C6 I²S RX ─┬─ AI 上行
Mic R ─┘                                                    └─ TF 本地录音分流

ESP32-C6 GPIO1/I²S TX ─ ES8311 ─ HT8691R ─ 8 Ω / 1 W Speaker
                              └─ 模拟播放参考 ─ ES7210 CH3

共享时钟：GPIO0 MCLK / GPIO3 BCLK / GPIO12 WS
```

固件契约：

- I²S RX 只能有一个底层所有者；AI 与本地录音在采集适配层分流，禁止两个任务同时读取硬件；
- TF 写入不得阻塞音频实时路径；队列必须有界并定义溢出、停录和文件恢复策略；
- codec 初始化、采样率、位宽、slot 和通道映射必须作为一个版本化契约冻结；
- ES7210 CH3 播放参考是否可满足算法需求，必须用原始 PCM 和回放/录音对齐证据确认；
- PA 开启顺序为时钟/codec/数据稳定后置 `PA_EN`；关闭顺序相反，避免爆音；
- 无 PSRAM 条件下先保证稳定采播和录音，再评估端侧重算法，不预设可运行完整 AEC/降噪模型。

## 7. TF、NFC、IMU、电池与电源

### 7.1 TF / SDSPI

- GPIO18 MOSI/CMD、GPIO19 CLK、GPIO20 MISO/DAT0、GPIO15 CS；DAT1/DAT2 未使用；
- 无 card-detect，引导时挂载失败不得阻塞主功能或形成重启循环；
- 采用低速初始化、受控提速、周期性有界探测、流式写入和断电后文件恢复；
- L1/L2 覆盖无卡、插拔、满卡、坏卡、慢卡、掉电和长录音。

### 7.2 NFC / PN532

- I²C 地址 `0x24`，模式绑带为 `I1:I0=10`；无 IRQ、无可控独立复位；
- 采用低频有界轮询，单次事务和业务等待均可超时退出；
- 仿真只能覆盖寄存器/协议状态机，读距、金属干扰、标签兼容性必须实机验证。

### 7.3 IMU / QMI8658A

- I²C 地址 `0x6A`，无 IRQ；采用轮询；
- 首板核验芯片 ID、轴向、零偏、量程和采样率；结构装配后重新确认轴定义；
- 当前硬件不支持用 IMU IRQ 做深睡唤醒，产品需求不得反向假设该能力存在。

### 7.4 电池与电源

- BAT+ 经 1 MΩ / 2 MΩ / 100 nF 分压到 GPIO2，ADC 输入约为电池电压的 `2/3`；采用 12 dB 衰减、校准和多次采样；
- LGS4056H 的 RPROG=5.1 kΩ，设计充电电流约 176 mA；`CHRG` 仅驱动指示灯，`DONE` 未接 MCU；
- MCU 不具备完整的充电中/充满数字观测，不能仅凭电压宣称“充满”；
- MASTER_SW 物理硬切 VIN→VOUT，应用必须接受随时断电；关键文件和状态采用增量持久化、原子提交和恢复扫描。

## 8. 启动与降级顺序

1. 设置 PA、背光、RGB、马达为安全关闭，输出复位原因、Flash 和分区诊断；
2. 初始化 I²C 100 kHz，探测五个固定地址；建立 PCA9557 安全态并 readback；
3. 初始化 ST7789，完成首帧后再开背光；
4. TF 低速挂载；无卡/坏卡只降级录音，不阻塞 UI 与联网；
5. 建立 I²S 时钟和 codec，再按顺序开启 PA；
6. 初始化 PN532/QMI8658A，所有失败均可超时并进入降级态；
7. 校准 BAT ADC 和 DPAD；
8. RGB 保持关闭或限亮显示启动状态；
9. 马达仅在供电稳定后执行短促自检；
10. 自检结果映射到串口、显示和结构化故障码，禁止无信息重启循环。

## 9. 首板验证最小矩阵

| Gate | 必取证据 | 通过条件 |
|---|---|---|
| G1 安全启动 | 限流电源、UART、复位原因、JEDEC ID、I²C 扫描、PCA readback、关键波形 | 可重复启动；外设默认安全；五地址行为符合装配状态 |
| G2 人机交互 | LCD 照片/视频、按键 ADC 原始值、RGB/马达电流与交互录像 | 显示方向/颜色正确；输入无明显误触；反馈不引发掉压 |
| G3 音频 | I²S 波形、codec 寄存器、原始多通道 PCM、播放录音、爆音记录 | 双麦/参考/播放通道映射可解释，采播稳定 |
| G4 录音 | 不同 TF 卡、长录音、满卡/坏卡/掉电恢复、文件哈希 | 音频实时路径不被写卡阻塞；文件可恢复或明确报错 |
| G5 联网/AI | Wi-Fi、协议、音频上下行、断网重连、OTA 日志 | 状态机可恢复，不泄漏资源，不静默失败 |
| G6 传感/电源 | NFC、IMU、BAT ADC 标定、充电/低电、硬切恢复 | 传感行为和电量估算满足 PRD，断电不破坏关键数据 |
